原因と変更

旧Worker版では、画面内を切り取った画像だけを保持し、指を動かしている間は新しい表示位置を描画側へ送っていませんでした。急な縮小で見える領域の欠落を、以前の青い線が操作中に消える例として再現しました。再設計版は変更した作品区画を別の表示処理へ渡し、作品全体の表示用画像を保持します。表示位置は操作中も受け取り、保持画像の合成で応答します。通常の移動・拡大・回転では、操作ごとのGPU画像の作り直しを省き、操作終了時にM08の精密な表示へ更新します。正式描画と作品区画の反映は操作中も続きます。変更区画を作品座標の画像として画面側にも疎に保持し、新しい表示画像のGPU処理中も、画面外だった場所をすぐ見せます。

入力を担当する処理からブラシ計算・正式GPU命令・表示GPU命令・画素読出しを分離しました。ブラウザー起動から監視し、画面側にGL/WebGPU描画面を作っていないことも検査しています。画面の保護画像、正式確定を待つ表示切替、描画終了後の120ms抑制、操作後の80ms抑制を新経路から撤去しています。ブラシの計算、128px区画の履歴、保存形式は再利用しています。

修正前後の計測

単位はms、正式反映のみ秒です。入力・表示更新間隔・rAFのp95欄は36条件それぞれのp95の中央値です。画面反映は要求した変換が線を2 CSS px以上動かせる大きさになってから、キャプチャ画像内でその移動を観測するまでの時間です。最初の微小入力からの時間も生データに残し、ゆっくり動かす時間と反映遅延を区別しています。画面更新間隔は線の重心が0.5 CSS px以上動いた異なる合成画像の間隔で、入力送信の間隔やキャプチャの負荷も含みます。rAFは処理周期の目安であり、画面が光った時刻ではありません。GPUの実行時間・占有率は未測定で、送信数・区画数・完了待ち時間を生データに記録しています。
