# Illustro Raster領域検査 v0.1

**人間による実線画検査待ち。精度の最終合否は未判定。**

`illustro-raster-region-lab.html` をPCのChrome等で開いて使用する。HTML内に全処理を含む。外部ライブラリ・AI・ネット接続・製品本体は不要。ファイルを直接開く動作はこの検査環境のURL制限により未確認だが、同じHTMLをプレビューサーバーで開いて操作を確認済み。

直接開く環境で動かなければ、このフォルダで `python -m http.server 8000` を実行し、ブラウザで `http://localhost:8000/illustro-raster-region-lab.html` を開く。

## 人間による検査

1. 自分で髪、毛先、顔、目、服、指、開いた線を描く。
2. 「領域を解析する」を押す。
3. 「元線画＋色分け」で意図した領域になっているか見る。
4. 「領域を選ぶ」で場所をクリック。「選んだ場所をメモへ追加」で番号と位置を記録する。
5. 「補助接続なし」と「形から補う」を比べる。補助の上限を変え、意図的な隙間まで閉じないか確認する。
6. ページ下へ妥協できない間違いを書き、「線画＋メモを保存」で検査データを保存する。

領域番号は再解析で変わることがある。結果の識別値と位置も記録する。保存したJSONを渡せば同じRaster・条件・拒否した接続・メモで再試験できる。

## 採用した仕組み

|処理|方式|
|正本|共有境界の両側がどの領域かを保存する平面分割。領域表に外周、穴、外側、隣接関係を記録。ブラシ幅を境界に持たせない。比較はDESIGN.md参照|
|Raster→境界|画素の濃さと透明度→濃い部分から薄い隣接部分を拾う→Zhang–Suen中心線化→画素格子の余分な辺の整理。幅情報は方向測定用の別データ|
|接続|線の続き、前方の線の途中、先端を閉じる、角の候補を別々の条件で生成。先端は既存経路・幅の縮小・閉鎖面積を利用。距離の加重合計は使わない。競合は保留|
|領域生成|交点で境界を分割→境界を一周→外周と穴を割当。最も内側の領域を画素の問い合わせデータへ書く。元線画の色による塗りつぶしは行わない|
|将来の修正|補助接続の拒否、明示追加用のデータ、範囲修正を足せる欄、接続の出所を保持。今回のUIは補助の拒否・解除まで|

参考：CGAL 2D Arrangements（領域表現）、OpenCV公式公開ソース（中心線化条件）、SelingerのPotrace論文（輪郭方式の比較）。同じ方式を丸ごと使用してはいない。

## 検証で確認した動作

数値は構造・実行検査の記録であり、人間が意図した精度の評価ではない。

- 13検査群。外側・穴・入れ子・隣接・交差・T字・重なり・極小多角形・同一入力の決定性等。
- 3×3画素の512通りについて、抽出前後の閉領域数が一致。
- 66 Raster画像 × 補助あり/なし＝132条件。各条件を2回実行。例外なし、閉境界の整合性・隣接対称性・全画素の割当・同一結果を確認。
- Rasterの決まった形では、細線～太線の輪、穴、T字、4/8 pxの開いた先端、4つ並ぶ先端、線の途中への接続の出力を数値で記録した。単に近い平行線には補助を追加していない。
- ブラウザで実際にペン操作→解析→描き足し→再解析、消しゴム→Undo→同じ結果、表示切替、領域選択、補助の拒否・解除、保存→Clear→読み込み→同じ結果を確認。
- 960×640の操作検査では解析処理の表示値が132～348 msの例を記録。一般的な性能保証ではない。

## 既知の弱点・未確認事項

- **tiny-loops**：6つ描いた輪のうち最小の1つが抽出マスクの時点で残らず、5領域になる。通常/薄い線/濃い部分の3設定とも同じ。中心線化後に消したものではない。極小のAA線は要改善。
- 上限12 pxでは**tip-gap-16/24**を補わない。どこまで補うべきかは人間の検査が必要。
- HTML見本の毛先4本では初期条件で補助3件・閉領域3件。2本目の先端はこの上限では閉じない。見本全体を合格とは扱っていない。
- 別の毛束でも形が似て同じ接続成分に属すと、根拠が間違った方向に揃う可能性がある。人間の実線画で誤接続を収集する必要がある。
- Rasterですでに触れた線、潰れた白い隙間から元の意図を復元できるとはしない。重なる線はRaster上の一つの境界へ統合され、元のストロークは復元しない。
- 中心線は画素精度。太い角・太い交差・塗りつぶした箇所で位置が不自然になり得る。滑らかな曲線への置換は未実装。
- 原画像の最大辺1600 px、中心線15万点まで。超過時はエラーを表示し元画像を保持。8Kや製品規模の速度・局所更新は未検証。
- ブラシ幅は分析の参考にするが正本の境界にはない。画素未満の領域は多角形データに残せても色分け画面で見えない場合がある。
- 意図的な隙間と描き損ねは同じ画像になり得る。必ず区別できるとはしない。保留・補助なし・拒否で人間が判断する。
- 実際のペンタブレットの筆圧、他ブラウザ、スクリーンリーダー、端末サイズの網羅検査は未確認。

## 再実行

HTML利用にはインストール不要。コードの検査はNode.jsで `node test-structure.cjs`。

Raster検査の再生成にはPython＋Pillowで `python generate-fixtures.py`、次に `node test-raster.cjs`。

HTMLの再生成：`python build-html.py`。`engine.js` と `template.html` が編集元。

`structure-verification.json`、`raster-verification.json`、`browser-verification.json` は実行記録。AIによる線画精度スコアや画像の合否判定は含めていない。
