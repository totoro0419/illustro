# Illustro — 全面再制作の進め方

> **合意した進行順序（2026-10-27）**
>
> **作るものを決める → 軽量化の仕組みを設計する → 設計図を描く → 実装する**

この順序は全面再制作の基本方針とする。個々の段階の成果は、[製品の基本理念・設計思想](PRODUCT_VISION.md)を満たすためのものとする。

## 第1段階：作るものを決める

- **対象：** Illustroの機能、UI、操作体系、制作フロー、画面ごとの体験、端末別の使い方など。
- **目的：** ユーザーが何を、どのように、どんな感覚で実現できるべきかを具体化する。
- **成果：** 実現したい機能・操作・品質・使用場面を確認可能な要求として整理する。
- **この段階では決めないこと：** 具体的な内部システム、採用技術、旧実装の再利用、実装手順。

## 第2段階：軽量化の仕組みを設計する

- **対象：** 体感応答性、描画中・描画直後の操作、処理負荷、メモリ使用量、表示の連続性など。
- **目的：** 第1段階の操作体験を、正確性・画質を損なわず、待たされずに利用できるようにする。
- **成果：** 軽量性と即応性を実現するために必要な仕組み・方針を設計する。
- **注意：** 単なる演算時間短縮を目標にせず、実際のユーザー操作を基準に考える。先に採用技術を固定しない。

## 第3段階：設計図を描く

- **対象：** 機能構成、内部構造、責務、機能間の関係、データ・操作の流れ、状態の一貫性など。
- **目的：** 第1・第2段階の要求と方針を満たす具体的な製品設計をまとめる。
- **成果：** 実装時に参照する整合した設計図・仕様。
- **注意：** 内部設計の都合で明示済みの要求を勝手に削除・変更しない。

## 第4段階：実装する

- **対象：** 設計図に基づくアプリ開発と検証。
- **目的：** 仕様どおりに動作するだけでなく、想定した制作体験を実際に実現する。
- **成果：** 動作し、要求に基づく検証ができるIllustro。
- **合格条件：** 実装の成功と製品体験の成功を区別する。要求を満たしたと確認できる場合だけ合格と判断する。

## 全段階を通じて守ること

1. **進行順序を守る。** まず何を作るかを定義し、それに合わせて軽量化・構造設計・実装を行う。
2. **旧実装を前提条件にしない。** 引き継ぐのはユーザーが明示した理念・要求である。
3. **仕様を理由なく変えない。** 必要な変更があるときは目的との整合を評価する。
4. **直感性 → 使いやすさ・軽さ・応答性 → 多機能性・表現力** の優先順位を守る。
5. **正確性と描画品質を犠牲にしない。** 軽く見えるだけの不正確な描画や破損を合格にしない。
