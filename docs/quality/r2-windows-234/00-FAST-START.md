## 目的・判定

計234機能（R2 143／既存91）。各機能の判定は「使える」「使いづらい」「使えない」の3つ。試せなかった機能は未検査として理由を記録し、合格に含めない。

## 初回だけ実施

1. ユーザーのWindows PCのEdgeに接続し、R2 URLを開く。クラウドブラウザーへの無断変更は禁止。
2. 新規作品を作成→Gペンで1本描画→Undo→Redo。ここが失敗する場合は本格検査を中止し、環境の問題と製品の問題を切り分ける。
3. この作品を検査用Aとして保存。赤・青・緑・白黒グラデーション、閉じた四角、隙間のある四角、細線、点ごみを描いて使い回す。別作品Bは必要になるまで作らない。
4. 実作品には触れない。副作用のある削除・復元などは検査用の複製だけに限定。

## 最小使用量での操作ルール

- 章内で同じパネルを開いたまま複数の機能を試す。必要な設定・作品を引き継ぎ、同じ前提動作を繰り返さない。
- 機能固有の設定と描画品質は必ず実操作で確かめる。共通Undo・保存は最終複合操作でまとめる。ただし独自の取消・履歴契約があるものはその場で検査する。
- 機能入口が見つからない場合は関連パネル・機能検索を各1回だけ調べる。見つからなければ使えないと記録。見つかっても操作が非常に分かりにくければ使いづらい。
- 失敗時は再試行1回まで。確かめたら再現手順・期待した結果・実際の結果を1行で記録。写真は判断に必要な場合だけ。
- 一つの機能の故障が次の検査の前提を壊した場合は、次を勝手に失敗判定せず未検査とし、独立に実行できる検査へ進む。
- Windowsで扱えない実際の筆圧・タッチ・端末専用UI・画面読み上げ等は未検査。画面幅の再現だけでAndroid実機の合格とはしない。
- 結果は章ごとにGitHubへ保存し、章内も15機能以上を処理したら一度保存。中断後は最後の確定IDから再開し、前の章を読み直さない。
- 成功時のログは「ID｜使える」のみ。不具合時「ID｜評価｜操作｜期待→実際」。重複した説明・途中報告・新規調査を避ける。
- アプリ本体への修正、PR統合、公開変更、ユーザーの作品変更は禁止。GitHubへ保存するのは検査結果のみ。
