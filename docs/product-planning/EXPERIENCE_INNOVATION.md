# 制作体験の問題分析と改善案

調査・策定日：2026-10-27（JST）。状態：**製品仕様案・未承認**。ユーザー指定の要求を除き正式採用ではない。実装・性能達成を示さない。

[文書案内](README.md) · [判断台帳](DECISION_REGISTER.md) · [品質要件](QUALITY_REQUIREMENTS.md)


## 根拠の区分

旧Illustroで描画直後に指操作が妨げられたことは今回ユーザーが明示した現象。原因は未確定。競合の個別制約は出典IDで示す。それ以外の障害は**設計上想定されるリスク・改善仮説**であり、全利用者の不満や全アプリ共通の実証済み事実ではない。各案は創造的提案と実現性検証を分ける。新発明/世界初/高速化の保証をしない。

| 作業 | 本来の目的 | 障害・リスク | なぜ起きると考えるか（分析） | 参考となる既存方式 | 対応案 | 複雑さ・誤操作への対策 |

| 別案を試す | 良い案を残し大胆に試す | Undoを戻すと後の案が失われる不安 | 作業履歴と名前付き案の区別不足 | AF-04、PR-01のUndo寿命 | EXP-06/17 | 容量制限を説明し、無限永久保存を約束しない。 |
| 保存・再開 | データを失わず続きへ | 保存中に新しく描いた分が保存されたか曖昧 | 作業保護と持出ファイルの違い | 旧save-recovery、今回の品質要求 | EXP-01/18 | 保護できていない時点を成功に含めない。 |
| 書出し・他アプリ受渡し | 狙った外観/編集情報で渡す | 書出して開くまで損失が見えない | 形式ごとの表現差と色/フォント依存 | AD-05、CS-03、KR-07 | EXP-19 | 事前検査と実際の往復結果を別評価。 |

| 端末・表示条件を替える | 同じ制作を続ける | 縮小UIで操作が隠れる、キーボードで適用が消える | 画面寸法と操作能力の混同 | PR-06、CS-05 | EXP-03/14/15 | 機能意味を維持し入口を適応、単指/数値の代替。 |

## 改善原理

能力の追加だけでなく、繰り返していた「探す・指定し直す・待つ・比較を記憶する・失敗の修正」を減らす。共通化するのは利用者に見える契約であって、内部方式ではない。表示だけ先行させる方法へ全てを押し込めない。範囲再利用、対象の可視化、局所取消、別案保護、依存の固定、書出し前の損失確認は、仮線表示以外の改善経路である。

## 改善案の詳細（全件：提案・未承認、実現性未検証）

### EXP-01 — 操作の受付と処理完了を分けて見せる

| 観点 | 内容 |
|---|---|
| 解決対象 | 描画直後・重い塗り・保存中に操作が止まる |
| 既存方式の問題・分析 | 処理完了を次操作の許可条件にすると、短縮しても待ちが残る。旧実機現象の根本原因は未確定。 |
| 提案する体験 | 全処理でまず操作が受理されたと分かり、表示操作と次筆は継続。完了前の結果を保存済みと呼ばない。 |
| 想定利点 | 処理の長さを指操作の停止へ直結させず集中を保つ。 |
| 想定欠点 | 受理済み操作が溜まると追従と確定差が広がる。誤って全て自由編集できると解釈されやすい。 |
| 他機能・参考元 | CAN/BRU/FIL/SAV、C-02/03/07。意味の競合は対象単位で説明。 |
| 操作性への影響・副作用対策 | 新しいモードは増やさず、全操作の共通振る舞いにする。 |
| 今後の検証 | 入力受付/見た目/確定の時間差、長操作列の順序とUndo、容量限界。方式と実現性は未検証。 |

### EXP-02 — 表示操作で途中の絵を置き去りにしない

| 観点 | 内容 |
|---|---|
| 解決対象 | 途中線や加工候補が原画と別に見える |
| 既存方式の問題・分析 | 表示中の要素の意味が分かれていると同時変形で位置関係が崩れる。具体実装原因を断定しない。 |
| 提案する体験 | 指を動かすと原画・途中線・選択・候補・ガイドが一枚の制作空間として動く。ペン接地中の解釈は比較。 |
| 想定利点 | 道具を持ち替えず構図や線方向を確認。 |
| 想定欠点 | 接地したペンの下を絵が動く時の線の意味が直感と合わない場合がある。 |
| 他機能・参考元 | INP/CAN/TRN/REF、DEC-02。資料窓は作品に固定したものかUI窓か明示。 |
| 操作性への影響・副作用対策 | 指ナビを常時利用、筆を無言に休止/再開しない。 |
| 今後の検証 | 接地継続/一時休止の比較、ペン静止・移動・指2本・ズーム回転・最終位置。 |

### EXP-03 — 対象と参照元を短く同時に見せる

| 観点 | 内容 |
|---|---|

### EXP-04 — 矛盾する編集だけに決定を求める

| 想定利点 | 必要な意思決定だけに集中できる。 |

| 操作性への影響・副作用対策 | 新モードでなく共通切替契約。保留を延々積み上げるUIにしない。 |
| 今後の検証 | 各組合せ、内部Undo、取消の局所性、別層編集→元候補取消、保存要求。 |

### EXP-06 — 別案を確定前に同じ条件で比べる

| 観点 | 内容 |
|---|---|
| 解決対象 | 頭で前の色/形を記憶して往復する |
| 既存方式の問題・分析 | 画面条件や倍率が違うと差の原因が分かりにくい。 |
| 提案する体験 | 色調/合成/グラデ/変形/案の比較は同じ位置・倍率で前後切替、必要なら並列。比較だけでは作品を変更しない。 |
| 想定利点 | 判断のための記憶負担とUndo往復を減らす。 |
| 想定欠点 | 並列は面積を使い、プレビュー保持は資源コスト。 |
| 他機能・参考元 | HIS/NDE/FX/GRA、PR-03新旧色、AF-04の状態比較を拡張。 |
| 操作性への影響・副作用対策 | 比較トグルを共通化し、全てに巨大比較窓を強制しない。 |
| 今後の検証 | 同条件表示、切替の速さ、確定前後一致、比較に含める選択/資料/Proof。 |

### EXP-07 — 一度直した区分を塗りと選択へ使う

| 観点 | 内容 |
|---|---|
| 解決対象 | 同じ隙間を毎回別ツールで直す |
| 既存方式の問題・分析 | FillとSelectionで参照・許容・境界が食い違うと修正が再発。 |
| 提案する体験 | 領域用線画で境界を一度修正し、同じ確認済み区分から塗り/選択を開始。普通の色差Fillも残す。 |
| 想定利点 | 人の修正を再利用し、細かい彩色を安定化。 |
| 想定欠点 | 線画変更後に区分が古くなる。解析誤りの検査が必要。 |
| 他機能・参考元 | LIN/FIL/SEL、手動判断と色の割当は別。永続IDや共有内部基盤は要求しない。 |
| 操作性への影響・副作用対策 | 専用層は必要時に作る。使わない制作を重くしない。 |
| 今後の検証 | 髪先/穴/顎/交差/近接の正誤、人の修正量、通常Fillより総手数が減るか。 |

### EXP-09 — 操作中の小さなUndoと確定後のUndoを分ける

### EXP-12 — 誤り候補だけを巡回して直す

| 観点 | 内容 |
|---|---|
| 解決対象 | 微細な塗り残しや線の穴を全画面から探す |
| 既存方式の問題・分析 | 小さな欠落は縮小表示では目立たず、拡大移動を繰返す。 |

## 提案が増えすぎないための審査

20案を20個の新ツールにしない。対象帯、共通の比較、適用/取消、保存状態、検索登録といった少数の入口へ統合する。各案は「導入しない場合の通常方式」でも制作を完結できることを確認する。採否は機能数でなく、総課題時間、誤操作、修正回数、初見到達、Canvas占有、入力応答、最終結果整合で比較する。改善が確認できない案は保留/改良し、独自性のため採用しない。

## 追加した不足テーマ

### EXP-21 — 保存と出力へ「どの時点か」を持たせる（改良推奨）

解決対象は、保存中に筆を加えた後で何が持ち出せるか分からない問題。全編集終了まで待つ案は中断、最後の瞬間の像を無条件に取る案は内容が予測できない。**要求時点を固定し、後続変更は別状態**を推奨。NB-08/09/10でSnapshot/保存/出力へ展開する。元のEXP-18は状態表示、EXP-21は内容境界を担当する。欠点は遅い先行処理を含む保存の完了待ちが残ること。制作自体は続け、時点と容量/失敗を明示する。検証は要求→後続筆→Undo→文書切替→再読込の比較。

### EXP-22 — 入力事故の一筆を救出候補にする（比較検証待ち）

解決対象は機器切断で長線を失う不安。全取消は安全だが有用入力も失い、常に途中を確定は不要な線を残す。**明示取消は全取消、事故中断は受理済部分を候補として提示**を推奨する。INP-005の通知から採用/取消、採用は一Undo。終端を推測して勝手にTaperを捏造しない。欠点は事故後の判断が一つ増えること。線端/筆圧/水彩/接続再開の飛び線を実機検証し、救出可能性を未検証のまま保証しない。

### EXP-23 — 制約を対象の場所で解く（改良推奨）

ロック/不足font/削除参照/非対応精度を単なるエラーで止めない。自動代替は速いが意味を変え、詳細設定へ毎回移動は探索を増やす。**理由＋最小の解決口**を対象帯/該当行へ置く案を推奨。LAY-008、VEC-006、LIN-007、IO-003へ共通化。通常操作に確認を増やさず、不能な時だけ解除/再指定/コピー変換を示す。長文通知と誤クリックが副作用。Phoneは一列、PCは該当行へ表示し、エラー後の復帰手数を比較。

### EXP-24 — 重い結果の「読込先」を固定する（採用推奨）

対象は資料読込/作品切替/層更新の遅い結果が別の対象へ届く問題。全操作ロックは待機、最後に開いている対象へ自動適用は誤編集になる。**開始時の作品と対象を維持し、閉じた対象へ結果を再出現させない**を推奨。NB-06/11/12とQR-06で検査する。欠点は古い結果の破棄/再試行を伝える必要があること。処理内容の並列方式は指定しない。A→B→Aの連続切替、資料を閉じて再追加、Undo後の更新を故障注入で確認。

### EXP-25 — 未使用の高度機能を制作から切り離す（改良推奨）

解決対象は、機能を使っていない普通のラフでも重くなる問題。機能削除は表現を失い、常時全機能を動かす案は応答/電池/熱へ負担。**能力は保持し、必要な時以外は不必要な恒常負荷を発生させない**を推奨（QR-19）。ユーザーに内部モジュール管理をさせない。初回利用の待ちが副作用なので、機能呼出しの受付/取消/代替作業はNB契約へ従う。未使用/使用文書で入力遅延・メモリ・熱・初回到達時間を比較する。遅延読込等の実装方式はここで確定しない。

## 重要方式の最終比較

- **ナビ**：描画継続/筆休止はどちらも一体表示と受付を満たし得る。直感性と誤線は実機で逆転し得るため、継続を第一比較案とし最終優劣は未確定（DEC-02）。ナビ待ちを代替採用しない。
- **未確定編集**：全自動確定は少手数だが作者制御を失い、毎回確認は制御できても頻用操作を阻害。局所衝突だけ確認を推奨。画面密度は同じ対象へ戻れる短い帯で抑える（EXP-04）。
- **塗り**：通常一タップ＋必要時直後調整は、常時候補確認より手数が少なく、全永続編集より意味が単純。領域区分の明示更新は別能力として共存させる（EXP-05/07）。
- **UI**：全露出/検索だけ/自動提案メニューより、頻用可視＋文脈入口＋検索から固定を推奨。覚える位置を保ち高度機能を発見可能にする。提案は固定スロットと混ぜない（EXP-03/08/13）。
- **履歴/保存**：全永久保存と直線Undoだけの中間として、固定案/通常Undo/復元/持出時点を別概念にする。概念の増加を容量と復帰先の見えるUIで補う（EXP-17/18/21）。

全25案は提案。実現性/利用者優越は未検証。試験結果が推奨を支持しなければ再評価するが、ユーザー指定の非待機/正確性/安全性の要求を引下げる根拠にしない。
