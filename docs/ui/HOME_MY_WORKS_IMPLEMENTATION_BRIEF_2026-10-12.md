## 0. 今回合意された仕様（勝手に変更しない）

1. **見た目の色はユーザーが選んだ「2番目の画像」**: 白〜青白の明るい基調、透明感のある淡い青／紫、適度な青の強調。暗色ホーム、派手な虹色、原色の大量使用、過度なガラス演出を避ける。
2. **配置は「3番目の画像」**: PC・タブレットのホームは左に制作の入口、右に広い特徴的なエリア。スマートフォンでは自然に縦配置する。
3. 左の操作順は**新しい作品 → マイ作品 → 前回の作業を続ける**。順番を変更しない。
4. **「ファイルから開く」は「新しい作品」の中の選択肢**。ホームに「ファイルを開く」を独立した大ボタンとして並べない。
5. **マイ作品は保存済みの作品を一覧・再開・管理する独立ページ**。ホームにダミー作品一覧を常設しない。
6. 右側は**アプリのトリビア／機能紹介**。カードを押すと機能詳細ページへ遷移する。紹介は実装済み機能に限定し、使い方と対応する機能へ行く入口を置く。
7. 描画画面のトップバーは既存の **Home / Save** を維持。Undo/Redoをトップバーに移さず、Left All Features / Right Workspace / Layer Pageの既存仕様を変えない。
8. QA用の「新規キャンバス」等を本番エディターの固定ボタンとして残さない。ただし**旧QA画面は変更／削除しない**。本番の機能操作は正式なUI導線に移し、既存の操作IDをいきなり削除せず置換時にテストを見直す。

## 2. ページ構成と遷移

```text
アプリを開く
  └─ Home [左側を主役 / 右側を機能発見]
       ├─ 新しい作品
       │    └─ 新規作成ダイアログ
       │         ├─ 空白のキャンバス → サイズ/背景 → 作成 → Editor
       │         └─ ファイルから作成 → .illustro選択 → 検証 → Editor
       ├─ マイ作品 → 作品一覧 (別ページ)
       │    ├─ 作品選択 → Editor
       │    ├─ 名前変更 / 複製 / 削除(確認) / 詳細
       │    └─ 新しい作品へ
       ├─ 前回の作業を続ける
       │    ├─ 復元候補1つ → 内容/日時を提示 → 復元 → Editor
       │    └─ 候補複数 → 候補選択 → 復元 → Editor
       └─ トリビアカード → 機能詳細 → 「使い方を見る / この機能を開く」
Editor
  ├─ Home → 安全な状態確認 → Home
  ├─ Save → .illustroの正式な保存（M05仕様を維持）
  └─ Left All Features / Right Document → 引き続き機能を発見可能
```

実装案のルートID: `home`, `my-works`, `new-document`, `feature-detail`, `editor`。URLは同一アプリ内の `#home`, `#my-works`, `#feature/<slug>` 等で表現可能だが、**QA起動判定は常に優先**する（旧QAの初期画面を変えない）。ルートIDは表示状態、復元状態、Document状態の変更と混同しない。

ブラウザの戻る操作・端末の戻る操作でも意図せず編集データを破棄しない。ダイアログが開いていればまずダイアログを閉じ、編集→Home移行では保存／復元保護状態を確認する。

## 4. ページごとの確定動作

### A. Home

- `新しい作品`: 一つの入口。タップすると `空白から作成` / `ファイルから作成` の選択を含む作成画面に進む。`ファイルから作成` は現時点で**.illustroを開くこと**を確実に実現。画像読み込みなど未実装形式は選択可能と誤認させない。
- `マイ作品`: 独立ページに移動。**中身が実データに接続できるまで公開画面で有効化しない**（空の機能一覧で代用しない）。
- `前回の作業を続ける`: `listRecoveryCandidates()` を利用する。候補無しは理由の分かる非活性表示または控えめな案内。複数候補を「最新っぽい」だけで無断復元しない。
- 右トリビア: 実装済み機能の内容のみ。画面に表示されたカード全文がクリック対象か、明示ボタンかを一貫させる。詳細を開き戻ってもホーム位置が保たれる。
- 初回起動（0作品、0復元候補）でも魅力的に見える画面。**ダミー作品サムネイルは表示しない**。

### B. 新しい作品

- `空白から作成`: 作品名、幅、高さ、背景（現在実装されているもののみ）を設定。値は実装で安全に検証。現状のCoreの `1–8192px` 制約から逸脱しない。大きな画像は端末容量に応じた注意が必要。
- サイズプリセット: 実機と用途に合う少数の選択肢を置く。プリセットを選ぶと幅・高さの数値に必ず反映。未対応のカラープロファイルや印刷機能は約束しない。
- `ファイルから作成`: OSファイル選択→`.illustro`検証→読み込む。失敗しても**現在の作品を失わない**。選択取消は完全に無作用。
- 編集中に新規作成: 現在の描画が保護されているか確認する。保存／保護が失敗した場合にデータ破棄へ進まない。

### C. マイ作品（独立ページ・実データ）

- 正式な作品ライブラリを新設。表示項目は**実際に端末内のIllustroが管理する作品**に限定。ブラウザのDownloads内を勝手に取得したように見せない。
- 一覧: 作品サムネイル、名前、最終編集日時、サイズ、保存状態（必要時）、コンテキスト操作。既定並びは更新日時の新しい順。同名は別 `documentId` として区別。
- 各作品の基本動作: `開く`, `名前変更`, `複製`, `削除`（確認と取り消しの安全設計）、`作品情報`。一度に全部追加する場合でも各操作は実データに正しく結び付ける。
- 一覧0件: 空状態の専用UIと `新しい作品` への入口。疑似カード無し。
- 異常時: 読めない作品は他の作品まで隠さず、該当カードを「修復/再読込」の扱いにする。作品削除はサムネイル消去だけで済ませない。
- 検索・並べ替え: 件数が増えても作品が探せるように配置を先に確保。最初の公開時点の対応範囲をUI上で明示する。
- **作品一覧 ≠ Recovery候補**: 復元セッション1個につき作品1件として数えない。作品IDを主キーとし、作業セッションは内部で紐付ける。

### D. 前回の作業を続ける

- ここは`マイ作品`の**下**、独立した入口。保存済みライブラリの「開く」とは異なる。
- 実際の復元候補の有無、更新時刻、対象名を確認してから表示。
- 作品の保存済み状態より保護済み作業が新しい場合は、差異があることを説明。**上書き／復元の前に適切な選択肢**を出す。
- 復元の対象は受け取った保護済みRevision。古い／破損候補や未保護データを勝手に最新作品として扱わない。

### E. トリビア・機能詳細

初期の紹介候補は既存機能に限り、例えば:
1. **キャンバスの回転と100%表示**（M08）
2. **強制入り抜き**（受入済みFoundation）
3. **レイヤー追加と切替**（M02）
4. **Undo / Redoの仕組み**（M03）
5. **透明に消せる消しゴム**（M04）
6. **作業を守る自動保存**（M05）

各項目に `id`, `title`, `summary`, `detail`, `illustration`, `targetAction`, `milestone` 等を持つ **データ定義**を用意。詳細画面には: 機能説明 → イラスト／短い操作図 → 使い方 → `描画画面で使う`（実装済みの機能に正しく移動）。リンク切れや未実装の機能ページを出さない。アート素材は著作権・利用許諾を確認し、作者不明の画像を無断で同梱しない。

### F. エディター側

- Homeを正式導線として有効化。戻る時に最新操作の保護が終わっているか確認。保存が外部ファイルであることと自動復元の意味を混同しない。
- 上部Saveは既存の`.illustro` 保存機能を維持。ユーザーの承認なしに「Saveの中身＝端末ライブラリだけ」などへ意味を変更しない。
- `.canvas-top` のQA的な固定ボタン列を**本番エディターでは廃止／整理**。新規作成はHomeへ、Openは新規作成へ、復元はHomeへ。別名保存・画像Exportは正式なDocument / All Features入口で到達できること。
- QAモードでは従来のテストIDや操作導線を維持できる分岐を設ける。以前のQAを壊して本番UIを整えることは不可。
- 色・ブラシの拡張（M09/M10）は左ツール欄・右Workspaceの既存分類に追加する。ホームの「新しい作品」などへ混ぜない。

## 5. マイ作品の保存設計（新規に必要な部分）

`PersistenceCoordinator` の現在の保存／復元の意味を壊さず、別の「ローカル作品ライブラリ」を実装する。

提案データ:
```ts
type LocalWorkEntry = {
  documentId: string;            // 一覧の安定ID（WriterEpochとは別）
  title: string;
  width: number;
  height: number;
  createdAt: number;
  updatedAt: number;
  previewRevisionId: string | null;
  previewKey: string | null;      // サムネイルは再生成可能な補助データ
  latestGoodRevisionId: string | null;
  hasRecoveryNewerThanSaved: boolean;
};
```

採用方針:
- ライブラリでの「作品を開く」は、その作品IDに属する**整合性確認済みの保存版**、および関連する**保護済み作業**を照合して実行する。復元作業を誤って消さない。
- **新しい作品は初期化が成功し、ローカルの作品データが安全に保持された時点でライブラリに登録**。名前や最終更新は作品の実際の状態に同期。
- モデルの`documentId`を唯一の一覧IDとして扱い、同じ作品を何セッションも開いても一覧が増殖しない。複製時のみ新しいID。
- 持ち運び用の`.illustro`ファイルを読み込んだ場合は、**ローカル管理用コピーを作ることを明示**し、外部ファイルへの自動同期があるように誤認させない。再読み込み時のID衝突・同時編集を解消する。
- 読み込み／保存／リネーム／削除の処理は、Worker等に寄せて描画の入力処理を止めない。
- ライブラリの一覧用メタデータは軽い索引として保持してよいが、**一覧の索引だけを作品の正本にしない**。作品実体との整合性検査・復旧手順が必要。
- サムネイルは変更のない作品に対して作り直さず、描画中の毎stroke全Canvas読取りを禁止。縮小・圧縮を待機中に行い、古い要求を破棄可能とする。
- 一時的なブラウザ容量不足・プライベート閲覧・ユーザーによるサイトデータ消去を想定し、**ローカルだけが永久に保証される**とは案内しない。必要に応じ外部`.illustro`としてバックアップ可能にする。
- `m05/sessions` を勝手に削除／再定義しない。`m05/documents` の既存保存版も自動削除しない。新しいライブラリ用置き場はバージョンを付け、段階移行を実装する。
- OPFSが利用不可な場合のIndexedDB fallbackを維持。異なる保存方式でも**マイ作品の意味・データ整合性**を一致させる。

**注意: 現状の`save()`が`activate-last-good`を常に呼んでいるとは確認できず、既存lastGood領域が全作品で埋まっているとは主張できない。移行時には実データ存在判定と再構築試験を行うこと。**

## 7. 必須の自動検査・端末検査

- 初回起動はHome、保存済み無しでも成立。0件のマイ作品を偽造しない。
- 新規作品→一筆→ホーム→マイ作品→作品を開く→絵が残る。
- A/B二作品を作り、それぞれ異なる線・サイズ・名前が復元される。2件が混ざらず重複しない。
- マイ作品で名称変更／複製／削除を行い、元データが正しく維持される。取消操作・端末容量不足でも破壊されない。
- 外部`.illustro`ファイル読込成功／破損ファイル読込失敗／OSファイル選択キャンセル。読み込み失敗時に編集中の絵を失わない。
- 自動保護済みだが明示保存前の作品／明示保存後に編集した作品／複数復元候補を区別する。
- Homeへの移動中に描画・保存・Worker処理が完了していない場合でもデータ喪失しない。
- ブラウザ再読み込み・オフライン・再起動後もライブラリ表示と実体読込が成立。IndexedDB fallbackも確認。
- 外部サイトデータ削除・保存領域不足等は適切に説明し、データがあるふりをしない。
- PC（例: 1440×900）、タブレット、Androidスマホ縦横で画面が切れず、タップが絵の入力へ誤配送されない。
- キーボード操作、Esc／戻る、フォーカス移動、タッチターゲット、`prefers-reduced-motion`。
- 右トリビアは**実在機能**のみ、全詳細リンクが有効で、絵を開く途中に意図せず別作品へ飛ばない。
- **M01–M08**旧QA URLを維持。M05 recovery/offline、M06 export、M07 shell、M08 DPR／Canvas操作／WebGL2・WebGPU、Brush 93 testsの回帰を実施。
- 単にテストが緑でも、スマホ実機での操作確認なしに「ユーザー合格」と書かない。
