# Illustro旧版再開 — 新版の技術を将来選択採用する方針（2026-11-10）

## 0. この計画の位置づけ

**開発本体は `totoro0419/illustro_old`。新版 `totoro0419/illustro` は、今後の開発で参考にする技術・設計の保管元。**

目的は「新版で発生した問題を旧版で直すこと」ではない。旧版を土台として従来の開発を再開し、**新版で新たに構築・検討されたシステム、アルゴリズム、操作設計のうち、旧版で使う意義が確認できたものを、必要な時点で採用すること**。

優先順位は一貫して、①直感的な操作、②使いやすさ・軽さ・体感速度、③多機能性。画質・操作・データ整合性も損なわない。

**この文書は今すぐ新版技術を移植する作業命令ではない。** 新版との一括比較や全面統合を旧版開発の前提条件にしない。

## 1. 再開位置と既知の制約

- この再開用ブランチは旧版 `investigate/M10-static-input-loss-2026-10-26` のコミット `d0b9523963b68a77af950be2f5369d2aaf96d04b` から作った。古い `main` から作り直したものではない。
- この旧版の系統には、PR #49 → #56–#60 → #63 → #64 の変更が含まれる。PR #61/#62など別系統の試験内容を現在の旧版動作に混同しない。
- **ペンを離した直後から本線確定までの指入力停止は、2026-11-10の製品オーナー判断に従い、端末側の問題として扱って無視する。** 今回の原因調査・専用修正・合格判定の対象にはしない。端末が原因と技術的に立証されたという意味ではなく、過去の調査記録は削除しない。
- 最新調査系統に診断用の変更が含まれる。実装を再開するときは既存機能と診断用コードを区別し、必要な通常機能を保存して始める。
- 以前のM01〜M10進行とユーザー承認済みの成果を尊重し、旧版に現在存在する機能を確認する前に「欠けている」「修正が必要」と推定しない。

## 2. 新版の扱い（候補と問題点を混同しない）

以下は**今後参考にできる可能性のある設計・仕組みの例**であって、旧版より優秀と立証済みの一覧ではない。

| 分野 | 新版で検討・実装された候補 | 比較する場合の観点 |
| --- | --- | --- |
| 表示の仕組み | 仮の表示と正式な表示を分け、対応する結果を一緒に切り替える仕組み | 旧版の既存方式より画質・速さ・安定性が良いか |
| レイヤーの表示 | 画面表示用の保持画像を使って可視状態を先に反映する仕組み | 旧版の表示速度・合成の正確さ・メモリ効率より優れるか |
| 描画アルゴリズム | ペンの入力記録、スタンプ間隔、補正などに関する新しい方式 | 旧版の線の自然さ・筆圧・始終端・体感速度を改善するか |
| 履歴・保存 | 操作順の確定、保存時点の作品状態を固定する仕組み | 旧版のUndo/Redo・作品復元・保存性能に実益があるか |
| 機能構造 | レイヤー・履歴・保存などを独立した役割として扱う設計 | 旧版に不足する機能を自然に追加でき、構造を複雑にしないか |
| UI | 新版で検討・実装された操作導線や見た目のアイデア | 旧版の直感性と作業スペースを向上させるか |

新版の参照固定点（2026-11-10時点）：`totoro0419/illustro` C03ブランチ `ab1b2bea55d117e833edccf88ebc816a775afbe1`。関連するPR #10 / #12 / #13、`docs/product-architecture/PRODUCT_ARCHITECTURE.md` 等。ただし設計案・実装・自動テスト・ユーザー実機承認は別の段階として扱う。

**新版で生じた問題を旧版へ持ち込まない。** 新版で報告された仮線の遅延や濃さの違い、Gペンの入り抜き、レイヤーのちらつき、ペン開始点・終点などは、**旧版でも実際に問題があると確認できない限り旧版の修正課題ではない**。それらを旧版の開発優先順位として指定しない。

## 3. 今後の進め方

1. **旧版の通常開発を再開する。** 既存の仕様・機能・ユーザー承認と、現在の開発段階を確認し、本来取り組むべき次の仕事を進める。旧版を新版へ作り替える作業は始めない。
2. **新たな機能や改善に着手する際、その分野に新版の有益な技術があるか調べる。** 全領域を一括監査したり、必ず新方式に置き換えたりしない。
3. **採否を比較して判断する。** 同じ条件で旧版の方式と新版の候補を確認し、直感的な操作・体感速度・画質・正確性・負荷・実装への影響を比較する。新版が優れる場合に限り、その仕組みを旧版に合う形で採用する。優位が不明なら旧版を維持する。
4. **採用する場合は局所的に実装・検証する。** 旧版の正常機能、旧作品、Undo/Redo、保存、操作方法を保護する。旧版より悪くなったら採用しない。自動テストと実機での体感は区別する。

### 判断の原則

- 「新版だから優れている」「新しいアルゴリズムだから採用する」は不可。
- 新版で独自に構築した仕組みは、将来の開発で利用できるよう参照情報として残す。
- 旧版の問題点と新版だけの問題点を厳密に分ける。
- 明示的な合格は、採用対象で実際に要求を満たした根拠があるときに限る。
- 描画直後の指入力停止は特例として対象外に保つ。

## 4. このPRで完了したこと・未実施のこと

完了したのは、**旧版を継続して、新版で得た優秀な仕組みを今後必要に応じて採用する方針の記録**のみ。通常アプリの実装、コード移植、比較ベンチマーク、実機検証はまだ実施していない。
