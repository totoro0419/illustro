# Illustro旧版再開 — 新版で得た設計を段階的に取り入れるための作業基準（2026-11-10）

## 0. 目的と優先順位

開発の正本は **totoro0419/illustro_old**。比較・参照先は **totoro0419/illustro**。旧版を捨てて新版へ移動したり、旧版の正常な機能を消したりしない。

目標は、一枚絵制作で直感的操作を最優先し、その次に体感速度・軽さ、さらに多機能性を高めること。単なる内部ベンチマーク改善を合格と呼ばない。仮線の追従性や描画品質、通常の画面操作の快適さ、作品データ・履歴の正確性を守る。**描画直後から本線確定までの指入力停止は、今回の開発で調査・修正しない例外**とする。

## 1. 正しい開始位置と今回扱わない既知問題

- 本作業ブランチの起点：旧版 `investigate/M10-static-input-loss-2026-10-26` の `d0b9523963b68a77af950be2f5369d2aaf96d04b`。
- 旧版 `main` は `bdc7135b51033982d90ea5dad104bb04fc107df2` の古い設計中心の状態であり、M10再開の起点にしない。
- この起点は PR #49 → #56–#60 → #63 → #64 の**系統を含む**。PR #61/#62等の非祖先実験を現行機能と誤認しない。
- **描画直後の指入力停止についての今回の決定（2026-11-10）**：端末側の問題として扱い、旧版再開の調査・修正・優先課題・合格条件から除外する。旧版PR #63の実機不合格、PR #64の調査内容、2026-10-26時点で根本原因未確定だった事実は履歴として残す。端末が原因と技術的に証明された意味ではない。
- 旧版の調査原典：`docs/investigations/input-loss-static-2026-10-26/REPORT.md` と `SOURCE_INVENTORY.md`。記述された構造上の問題（F1: 分割されないメイン側の計算・画像取込み、F2: 指操作状態が描画負荷制御に届かない、F3: GPU仕事量上限が最初の1ジョブを拘束しない）は、入力消失の**直接原因と確定していない**。
- 新版参照の現在固定点：`totoro0419/illustro` の C03ブランチ `ab1b2bea55d117e833edccf88ebc816a775afbe1`（2026-11-10確認）。新版PR #10/C01、#12/C02、#13/C03の実装・検査結果と、`docs/product-architecture/PRODUCT_ARCHITECTURE.md`の設計案を混同しない。C03も全機能の実機受入は未完。

## 2. 新版から取り込みを検討する仕組み（自動採用ではない）

| 領域 | 新版で確認した内容・候補 | 旧版に導入する際の条件 |
| --- | --- | --- |
| 入力の正確性 | 物理ペン開始時の筆圧0、同時刻に異なる位置の入力、離筆点の扱いを改良（C02）。 | 旧版の既存正本入力・筆圧・補正と比較。始点と終点を失わず、二重線・位置ずれなし。指描・旧ブラシも維持。 |
| 仮線の質 | 仮線を別経路で先に見せる、Gペンの大径スタンプ間隔を調整、鉛筆・消しゴムの表示差を修正対象とした（C02/C03）。 | 仮線はペン先に遅れないこと。濃さ・形状・始終端が正式結果と一致すること。旧版の質を下げない。 |
| 表示切替 | 仮線／正式結果／表示キャッシュを分け、正式画像準備後に一体で表示を置き換える設計（C03・製品設計）。 | 仮線の消失、本線の二重表示、チラつき、空白、黒い矩形、確定時の描き直し演出を防ぐ。画像完成待ちで画面操作を止めない。 |
| レイヤー | 表示専用の保持画像を利用した目ボタンの即時反映と、正式合成への後続切替（C03）。 | 通常合成だけでなくグループ・マスク・特殊合成の見え方が正しいこと。非対応を黙って近似しない。表示切替と保存画素を混同しない。 |
| 操作優先 | 操作受付、画面の移動・拡縮・回転、裏の正式計算・保存を役割で分ける設計。Worker利用とコマンド順守の工夫（C01/C03）。 | 旧版には既存の保持シーンとWorkerがある。似た機構を重ねず、競合・同期区間・メッセージ複製負荷を読んで必要部分だけ改善する。 |
| 履歴・保存 | 一筆を順序どおり登録し、保存を要求した時点の作品の版を固定する設計（C01/C03）。 | 旧版のUndo/Redo・マイ作品・保存・復元を保護。保存途中の後続操作やUndoで保存対象が変わらない。旧ファイルの読み込み互換性を壊さない。 |
| UI | C01のAurora Frost（オフホワイト・青系配色・軽い装飾）。 | 既存機能の配置と操作導線を尊重し、ペン・指の当たり判定と描画速度を悪化させない。見た目の採用は別途判断。 |

これらは「候補」であり、新版での実機効果の確認範囲は個別に違う。C03 PRがDraftであること、ブラウザーの自動試験と実機体感評価が別であることを保持する。

## 3. 安全な実装順序

1. **現状固定・比較**：旧版起点の実装と旧版M01〜M10の挙動を整理。旧版と新版それぞれの入力→仮線→正式描画→表示→履歴→保存を図にし、重複する仕組みと違う仕組みを特定する。既存機能の確認一覧、既知不具合一覧、性能と画質の比較条件を作る。
2. **新版の改善候補を優先順位づけ**：旧版の描画品質・仮線の見た目と追従性・レイヤー切替・履歴・保存を比較し、実機で効果が確認できた改善から選ぶ。**描画直後の指入力停止の切り分け・原因究明・専用修正は行わない。**
3. **改善を一系統ずつ実装**：まず線の始終端・仮線の一致、次に仮線から本線への一括切替・レイヤー表示、次に履歴・保存。必要な仕組みだけを旧版の既存構造に適合させ、直接のファイル丸ごとコピーや無根拠な設計置換を行わない。UIは既存操作系を壊さないことを確かめて検討する。
4. **変更ごとの自動検証**：型・単体・ブラウザー検証に加え、太いGペン、鉛筆、硬い消しゴム、連続筆、通常の指操作・拡大縮小、レイヤー表示、Undo/Redo、旧作品読み込みと保存を確認。新旧の画質と体感応答を比較する。既知の描画直後の指入力停止は検証の合否判定に含めない。元の良さを壊す変更は採用しない。
5. **Android実機での判定**：仮線がペンに追従し正式結果と一致すること、通常のキャンバス操作が快適であること、レイヤーON/OFFに待ち・チラつきがないことを確認する。ただし**描画直後から正式確定までの指入力停止だけは合格条件から除外**する。ブラウザーテスト成功だけでその他の品質を合格とはしない。

## 4. 運用ルール

- 旧版 `main`、既存PR、旧作品データ、新版 `illustro` はこの文書作成では変更しない。
- 実装は本再開用ブランチから必要に応じて小さな検査・修正ブランチに分岐する。既存機能を残し、戻せる差分単位にする。
- 「構造上確認したこと」「実機での効果が未確認なこと」「根本原因として立証されたこと」を区別する。描画直後の指入力停止は端末側の問題として扱うという**開発上の判断**であって、根本原因の確定ではない。対象に残る機能の合格宣言はユーザー実機での確認を含める。
- 新版の設計思想を尊重しても、旧版の既存機能を一律に置き換える権限にはしない。使いやすさ、体感速度、正確な画質の達成を最優先する。

## 5. 再開直後の達成条件

現時点では作業ブランチと移行指針の準備段階。**アプリの不具合修正・機能移植・動作検証はまだ行っていない**。最初の実装に入る前に、両版の処理経路と再現条件を整理し、改変対象を根拠付きで選定する。
