**Work自身のブラウザーで公開アプリを開き、実際に操作して234機能の使い勝手を検査してください。** 「使える／使いづらい／使えない／未検査」で判定し、使いづらい箇所には「こうしてほしい」を1～2文で残す。機能の存在やコードだけで合格にしない。

まず `docs/device-audit/WORK-EXECUTION-ROADMAP.md` と `docs/device-audit/work-steps/00-BOOT.md` **だけ**読み、P00→P12を順に実行。**次に必要な1ファイルだけ読み**、台本の102操作で作品・画面を引き継いで検査。 `WORK-COVERAGE.csv` はID対応表、`01-RESULTS.csv` は234行の結果、`02-DEFECTS.md` は問題の記録、`WORK-RUN-PROGRESS.md` は中断再開位置。各段階の末尾でGitHubへまとめて保存。

すでに計画済みなので再設計・無関係なコード調査・冗長な検証・アプリ修正はしない。画面で入口が無ければ該当パネル、すべての機能、検索を各1回だけ調べ「使えない」。実機ペン/タッチ、外部ファイル等が無い時は操作したふりをせず理由付き未検査とする。問題でも一度だけ確認して後続を続ける。同一原因は一つの問題番号に集約。時間超過時も重要機能と最後の20分の保存・再取得を優先。

最後に234件の各判定件数、問題と改善案、未検査理由を集計し、GitHubへ保存したデータを再取得してから簡潔に報告してください。途中確認は不要。**今回は本番実操作まで行い、結果が保存されて初めて検査完了**です。
