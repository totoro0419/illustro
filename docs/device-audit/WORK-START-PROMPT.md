検査準備PR：https://github.com/totoro0419/illustro/pull/113  
結果保存ブランチ：`qa/r2-device-audit-prep-2026-11-23`

## 最重要目的
**Work locallyでユーザーのWindows PC上の実際のブラウザーを操作し、Vercelで公開されたIllustro R2の234機能を、5時間の使用量枠1回でユーザー体験として検査してください。** 目的は厳密な仕様適合証明ではなく、**使いづらい点・使えない点・描画品質や快適さの欠陥をできるだけ多く発見し、改善案とともにGitHubへ保存すること**です。

**クラウド上の別PCやGitHub Pages旧URLへ切り替えない。** このPCでクリック・文字入力・マウス描画を実行してください。検査URLはユーザーがアクセス可能と報告済みですが、R2の実画面・操作可能性は開始時に独立確認してください。旧P0 Prototypeの黒画面、起動不可、権限上の問題なら成功としない。必要なら一度だけ再読込して、実際に何が起きたか記録する。

## 実行
1. `docs/device-audit/PC-SETUP.md` に沿ってWindows PC内のブラウザー操作を確認する。初回の新規作品作成・描画はそのままP00で再利用し、同じ操作を重複させない。
2. `docs/device-audit/WORK-EXECUTION-ROADMAP.md` と `docs/device-audit/work-steps/00-BOOT.md` を読む。**P00→P12の13段階・102操作**を順番に実施。毎回、次に必要な台本1ファイルだけ読む。既存ロードマップの再設計、旧版827件検査のやり直し、無関係なコード調査はしない。
3. 実操作で234機能をそれぞれ **「使える／使いづらい／使えない／未検査」** と記録。使えるなら判定のみ。使いづらいなら問題と「こうしてほしい」を1〜2文。使えないなら試した操作と現象。触れない機能は理由付き未検査。**コードの存在や画面表示だけで「使える」としない。**
4. 同じ作品・画面を使い回し、詰まった操作の再試行は原則1回まで。同一不具合はまとめて記録し、他の検査を続行。タッチや筆圧などWindows PCに実機入力手段がない項目は合格扱いにしない。
5. 検査素材は`docs/device-audit/QA-FIXTURES.md`を参照し、WindowsにZIPが展開済みなら使用。素材がないときは代替できる操作を優先し、入手不能な形式だけ理由付き未検査にする。素材探索で時間を浪費しない。
6. 各段階終了時に `docs/device-audit/01-RESULTS.csv`・`02-DEFECTS.md`・`WORK-RUN-PROGRESS.md` をGitHubの結果保存ブランチへまとめて保存。**最後の20分相当は集計・GitHub再取得・234行の重複／欠落確認に確保。**
7. **アプリコード修正、Vercel再設定、PR統合はしない。** 実装の完成と検査完了を混同しない。

## 最終報告
実際にPCで操作した件数、各判定の件数、重要な問題と改善案、未検査理由、検査したVercel URL、GitHubへ保存したファイルとコミットを簡潔に報告。ユーザーへの不要な確認待ちを挟まず進める。**5時間枠を使い切ることが目標ではなく、1枠内で最大限の検査を実行し、結果の保存まで終わらせることが目標。**
