## Workが行う順番

1. **WindowsデスクトップアプリのWork locally**で開始。[PC-SETUP.md](PC-SETUP.md)に従い**PC内のブラウザー**（アプリ内ブラウザーまたは許可済みChrome）でR2 URLを開き、Workが実際にクリック・入力・マウス描画できるか確認。クラウドブラウザーへ自動で切り替えない。PC操作が許可されなければその事実を記録し、PCで検査できたと偽らない。
2. 接続に成功したら**このロードマップと `work-steps/00-BOOT.md`だけ**を読み、本番を実行。OS・ブラウザー・入力手段・公開版コミットを進捗へ記録。検査用ファイルの場所は[QA-FIXTURES.md](QA-FIXTURES.md)参照。
3. P00で作品A（1200×900白背景）、作品B（小さな透明作品）を作る。P02で線画/色層を用意し、描線・色・塗りを使い回す。P09はAから書き出した画像を資料/取込で再利用。破壊操作は複製作品に限定。
4. P00→P12を順に、**今の1ファイルだけ**読み、各「Pxx-yy」の操作をそのまま実行。画面・層・設定を引き継ぎ、操作がまとめて確認する機能IDそれぞれについて実際の振る舞いを観察。旧 `steps/` や旧827の詳細条件へ戻って台本を再設計しない。
5. 「使える」は判定のみ。「使いづらい」は何が不便か＋こうしてほしいを1～2文。「使えない」は押した場所と失敗を短く。**未検査**は機器・ファイル・権限等により本当に操作できない場合や未着手の場合だけ、理由付き。**入口がない場合は原則使えない**（該当画面・すべての機能・検索を各1回だけ確認）。
6. 詰まったら同じ操作の再試行は最大1回、Undo/取消/別の作品で続行。同一原因は不具合番号1件に関連IDをまとめる。後続まで試せないものは未検査「上流不具合 D-xxxで阻害」とし、実施したことにしない。
7. 各段階の終了で [01-RESULTS.csv](01-RESULTS.csv) の**該当行だけ**更新、問題がある場合だけ [02-DEFECTS.md](02-DEFECTS.md) に短記録。 [WORK-RUN-PROGRESS.md](WORK-RUN-PROGRESS.md) に最後の操作IDと次のファイル、済/未検査件数、公開版コミットを更新してまとめてGitHubへ保存。次段階では前の台本を再読込しない。

## 使用量・時間の守り方

- Pごとに現在の台本だけ読む。全234行の旧詳細指示を毎回読み直さない。新CSVは旧原本より短くし、結果の更新量を減らした。使える時はスクリーンショット・長文報告を省略。
- P02で閉じた線・隙間線・色面を作ったら、塗り、選択、変形、合成、効果で再利用。効果は同じ一覧を開いたまま個別メニューを巡る。Undo/保存は必要な場面だけ。
- 予定超過時は代表操作1回へ縮小し、重要な新規作品・描画・補正・塗り・レイヤー・Undo・保存・主要UIと未実施理由を優先。**検査していない機能を「使える」で埋めない**。
- ユーザー向けの途中報告は必要最小限。問題と結果を継続保存する方を優先。大規模なコード調査・アプリ修正・PR統合は禁止。

## 環境によって確認できないもの

- WorkのPCブラウザー操作だけでは、実際のAndroidタブレットのペン・筆圧・傾き・ボタン・手のひら・指の多点操作、実スマホのソフトキーボード等を「使える」にできない。表示幅を変えて見ても実タッチの代用にはならない。機器がなければ該当IDを未検査にして残す。
- [検査用ZIP](QA-FIXTURES.md)のPSD・ORA・TIFF・SVG・AVIF・EXR・ICC等を最初から使う。PSB・HEIF・旧形式等、ZIPにない入力用実ファイルが存在しなければ、画面で試せる書出しと実入力を区別し、実入力未検査を理由付きで残す。対応形式を宣伝文だけで使えるとしない。
- アプリが起動しない時は1回再読込・既存状態からの再開を試し、起動不具合として記録。ブラウザーから操作できない状態をコードだけで合格にしない。起動を直すための修正には移らない。

## 検査環境の守り方

- 操作は**Windows PC内のデスクトップWork**から開始し、アプリ内ブラウザーか許可済みChromeを使用する。オンラインのWorkを選ぶとクラウド上の別環境になるため、PC操作実績として数えない。
- P00の前にマウスでクリック・描線・キーボード入力の3動作を実行して入力可能性を確かめる。マウスのテストで筆圧やタッチの実機確認をしたと扱わない。
- 外部ファイルは事前準備ZIPから読み込み、対象形式が実際に開けたかで判定する。ZIP未配置なら作業を止めず生成済みPNGを共用し、不足形式は理由付き未検査として残す。
- 30分ごとの進捗チェックや長文報告で時間を使わず、**各P終了時に結果と再開位置を保存**する。最終20分はGitHubへの結果保存と読み直し専用。
- 操作不能・権限拒否は環境障害と機能不良を分ける。利用可能な代替手段を一度だけ試し、不可ならPC検査ができないことを明示。別PCのクラウド実行を代替しない。

## 完了の定義

**全234 IDが結果表に残り、操作したIDだけに実体験に基づく判定が付いている。** 使いづらい・使えない結果には短い現象と改善案、未検査には理由。問題番号は重複再現をまとめ、端末情報と公開版を残す。結果と進捗をGitHubへ保存し**再取得して欠落・重複・判定数を確認**する。できない箇所を「全部完了」としない。修正担当へは不具合台帳を渡す。
