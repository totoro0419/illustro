# R11 — 元画像を保持する非破壊変形と、表示位置での直感的な編集

日付：2026-10-30 JST
状態：**主要6アプリの一次資料比較から導いた基本設計の推奨結論**。ユーザー個別の明示承認・実機性能・詳細実装は未確認。今は基本方針決定の段階。

## 結論

**画像・文字・ベクターなど元の編集可能なデータを保持し、通常の移動/拡縮/回転/遠近/メッシュ変形では原本へ繰り返し補間を焼き込まず、変形パラメータと表示用評価結果を別管理する。** 必要な場合にだけ明示的にラスタライズ/固定化する。

本線・素材の意味を変えず、変形中もキャンバス操作・次の入力を妨げない（R01/R02）。画質優先だが、単なる非破壊化のために普段の描画が難しくなるUIは避ける。

## Illustroに採る基本方針

1. **原本と変形パラメータの分離**：複数回のアフィン変形を結合できる場合は、原本を評価する変換をまとめて最終出力を一回サンプリングする。全ての非線形変形が行列結合できるとはしない。Undo/Redo/保存で原本と変形情報を保持。
2. **普段の操作は直感的**：変形ハンドル、ピンチ/回転/移動、数値入力、スナップの入口を用意。画面表示座標と編集する文書座標を正確に分離。**表示操作のズーム・パン・回転で作品画素を書き換えない**。
3. **変形後も描ける仕組み**：可逆な変形なら描画位置を原画像の座標へ写して編集する候補。非可逆/重なりがあるメッシュ変形は一意な逆写像がないため、**見えている画面位置へ修正する別の描画レイヤー・追加入力**を使うなど、無理な原本書換えを避ける。どちらの描画が変形と一緒に再移動するかの意味をUIで明確化。毎回のラスタライズ強制はしない。
4. **ピクセルアートは別契約**：整数座標の平行移動と90度単位の回転/反転など画素値をそのまま再配置できる操作を優先する。必要なサイズ変更では最近傍や面積平均等を明示選択し、ぼやける補間を自動強制しない。
5. **文字・ベクター編集性**：字形/テキスト内容/縦横書き/IME未確定文字、ベクター点・線幅を維持して変形。無断ラスター化しない。ラスタしか扱えない機能が必要なら、非破壊の表示用結果を生成するか、明示確定を要求する。
6. **高速描画**：変形中の即時表示は近似プレビューを認め、正式な結果は正確に計算する。変更があるタイル/タイル内部だけ再評価し、下地/周辺タイルの参照範囲をR05に従って処理。R06表示用合成キャッシュは正本ではない。
7. **物理限界の明示**：高品質原画像を保持しても、本来存在しない細部を拡大復元できるわけではない。「繰り返しの再サンプリングで失われる情報を抑える」という意味での劣化防止。
8. **範囲外の画素も保護**：回転/移動でキャンバス外へ出た原本の画素を削除しない。最終的なExportは指定した領域を評価する。

## 2026-10-30 — 非線形変形の性能懸念に対する推奨修正

ユーザーの懸念：「歪みとか重くなりそう、大丈夫？」

**非破壊の元データ保持と、毎回の歪み計算は同じではない。** 元画像と変形パラメータは保護しつつ、既に評価した結果を表示用タイルとしてキャッシュし、変形が変わらなければ通常の表示・ナビ・描画のたびに全画素の歪みを再評価しない。

- **軽い変形（平行移動、回転、拡縮等）**：行列変換と表示時サンプリングを第一候補とし、無駄な再ラスタライズを避ける。GPU対応が十分な環境はGPUを使い、未対応時の正しいフォールバックを残す。
- **複雑な変形（Warp、Mesh、Liquify等）**：操作時はR01/R02と同じく入力に追従する軽量プレビューを先行し、正確な正式表示はタイル／dirty範囲ごとに計算。完成済みの変形表示結果は**再生成可能なキャッシュ**として保持し、元画像や変形設定が変わった時だけ依存する結果を失効させる。
- **連続した非線形変形**：複雑な変形の評価を無制限に毎フレーム積み重ねない。表示用の合成・評価済みキャッシュを優先し、元変形データは保護。可逆でない変形を強引に逆写像へ押し込まない。
- **入力の優先度**：指ナビ、ペン入力、仮線を進めつつ重い変形計算も止めない。無関係な部分は再計算しない。GPU/CPU時間とメモリ消費が競合するので、速度は未保証。
- **性能の判断**：画質、変形更新遅延、通常筆への干渉、メモリ、タイル再評価回数を実機で検証。ユーザーに意図しない破壊的ラスタライズを強制しない。

一次資料：Kritaは通常のアフィン変形と重いWarp/Cage/Liquifyを区別し、後者の非破壊変形更新は3秒ごとと説明する（https://docs.krita.org/en/reference_manual/layers_and_masks/transformation_masks.html）。同じ更新間隔をIllustroで固定採用する意図ではない。KritaのTransform ToolではCageのプレビュー精度と本計算精度の個別調整も説明されている（https://docs.krita.org/en/reference_manual/tools/transform.html）。

これは**研究における性能上の設計制約・修正案**であり、当該細目のユーザー承認や性能達成ではない。

## 2026-10-30 — ユーザー発案：変形にも独立した仮画像を適用

提案：「それと変形の時も仮画像の考え方使えないかな？」

**評価：特に歪み・メッシュ・液状変形で有望な設計候補。** R01/R02で認めた「先行表示と正式画素の分離」を変形操作にも共通化する方向と整合する。ただし正式採用・速度改善は未検証。

- **操作中の仮画像**：元画像または最後に確定済みの表示結果から、ユーザーの現在の変形パラメータに追従するプレビューを独立に表示する。単純な移動・回転・拡縮では、高速なGPU幾何変換で十分なら無理に低画質化しない。複雑なWarp/メッシュ等では可変解像度・粗いメッシュなど、必要ならプレビュー精度を一時的に落とす。
- **確定版を別で正しく計算**：変形後の原本データとパラメータを正本のまま保持し、正確な結果をdirtyタイル単位で計算する。正式表示の準備ができた領域から欠けや二重表示がないよう仮画像から切り替える。正確な結果の生成中も入力・ナビを妨げない。
- **編集中の連続変形**：操作中に毎サンプル厳密変形をやり直さない。仮画像は最新入力を反映し、厳密計算が不要に古くなった場合は不適切な結果を公開せず、必要な仕事だけ再評価する。確定Transactionの時点とUndo/Redo順序は維持する。
- **画質・座標の制約**：仮画像が一時的に粗くなっても、表示位置・形状・選択対象との座標整合を守る。近似プレビューを作品に保存しない。過去に合意した変形後の描画、逆写像不能なWarp、R06の合成レイヤーと連携が必要。
- **計算コストの注意**：仮画像生成やGPU転送に固定費があるため、全ての変形へ強制せず、軽いアフィン経路と重い非線形経路で使い分ける。操作中の応答、確定速度、CPU/GPU・メモリ干渉は後日検証。

**現在の段階では「変形中の仮画像＋正確な正式計算の分離」を有力な基本設計候補として記録し、個別アルゴリズムの固定はしない。**

## 後工程で検証するが今は固定しないもの

- アフィン、射影、メッシュ変形それぞれの内部表現と高精度な逆写像の可否。
- 筆圧や位置が変形後にどの座標系で評価されるか、シーム/折り返し/筆の重なりを含むペイント契約。
- プレビューの近似許容差、正式確定タイミング、タイル再評価、GPU/CPUコスト。
- 画素・透明度・色空間ごとの補間カーネル、エッジAA、HDR/16bit精度、ソースのオーバーサンプリング。
- UIの「元画像への編集」と「表示位置への修正」の選択と、複数変形・Undo/Redoとの互換。
