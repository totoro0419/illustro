# R03 — 中心線方式の独立試作・初回ブラウザ実験（2026-10-29 JST）

## 位置づけ
ユーザーが提案した「中心線＋太さ」を重点検証するため、**Illustro本体とは独立した**ブラウザ試作を実行した。現時点で製品GPU、Android入力、筆圧・湿式、実現可能な正式採用条件を検証したものではない。

- 環境：Linux x86_64、Headless Chromium 144.0.7559.96、Python 3.13.5／Playwright。
- 領域：448×224px。直線・曲線、直径10px/48pxの4条件。各方式2回の事前実行後、18回実行の**中央値**。
- A：0.5px程度の軌跡間隔でCanvas2D円dabを繰り返し描き、RGBAのαマスクを取得。
- B：Canvas2Dのパスstroke（丸端・丸join）で被覆を描いてαマスクを取得。**輪郭ポリゴンを明示的に組み立てる実装ではない**ことに注意。
- C：中心線の線分と直径から32pxタイルごとの関連線分を集め、画素中心と各線分の最短距離で被覆率を評価。JSのCPU実装、線端1pxの簡易AA。タイル内線分探索は未最適化。
- A/BはCanvas2Dネイティブ描画、CはJavaScriptの画素ループ。API・実装言語の条件が異なる**探索的比較**で、数学的アルゴリズムの純粋な速度優劣を意味しない。
- 各方式のマスクへ同一の非蓄積半透明または座標依存テクスチャを適用する処理も実施。ただし半透明の反復flow、Smudge、テクスチャ筆先端の時系列合成は未比較。

## 速度（ms、18回の中央値、小さい方が速い）

| 軌跡 | A dab反復 | B Canvas2Dパス | C 中心線＋タイル |
|---|---:|---:|---:|
| 直線・直径10px | 6.5 | 3.0 | **1.3** |
| 直線・直径48px | 8.3 | **2.9** | 6.1 |
| 曲線・直径10px | 5.1 | 2.9 | **1.9** |
| 曲線・直径48px | 9.0 | **3.4** | 4.6 |

A/BにはCanvas2Dからの`getImageData`読出し時間を含むが、Cは計算結果がそのままtyped arrayであり、**CPU↔GPU readbackの負担まで統一した比較ではない**。GPU/Canvas2Dバックエンドは計測しておらず、ブラウザ内GPU timeや実GPU効率も不明。

## 出力差（8bit被覆マスク、Bとの画素単位平均絶対誤差を画面全画素×255で正規化）

| 軌跡 | A vs B | C vs B |
|---|---:|---:|
| 直線10px | 0.000021 | 0.000021 |
| 直線48px | 0.000126 | 0.000108 |
| 曲線10px | 0.002421 | 0.000410 |
| 曲線48px | 0.002915 | 0.000526 |

**画面全体で平均した誤差なので、エッジの局所的な差異を過小評価し得る。** CのAAは近似であり、bit一致・同品質合格ではない。半透明/テクスチャはこの被覆マスクに共通の画素関数を適用しているだけなので、完全なブラシ意味同値の証明ではない。

## 今回言えること

1. Cは少なくとも一部条件で実行可能であり、単純dab反復よりこの実装条件下では低い中央値を示した。
2. Cはすべての条件でBより速いわけではない。太い直線・曲線ではBが速かった。
3. Cの輪郭・被覆はBに比較的近いが、画素一致ではない。実装の差を含む。
4. 不透明に限定しない研究には妥当性がある。ただし蓄積flow、筆圧変化、テクスチャの先端作用、湿式/混色は別途検証が必須。

## この試験で正式決定しないこと

- **Cの全ブラシ採用・Bの不採用は決定しない**。
- GPU WebGPU/WebGL2の描画経路、高精度色・α、タイル確定・仮線置換・履歴・保存を含む結果は未実施。
- 次段階は同一GPU/CPU評価経路・同一画質と等しい総処理境界でのB/C比較、筆圧/幅変化、手描き入力・連続筆、蓄積半透明・テクスチャ・混色の独立オラクル比較、Android実機での追従と入力配送試験。
