# R13 — 必要部分からの段階的入出力と能力別の損失説明

日付：2026-10-30 JST
状態：**ユーザーが基本方針を承認**。具体的codec・対応形式・互換率・性能は後工程で検証。

## 基本方針

**作品の必要データから段階的に読み込み、出力も必要な画素・レイヤー・領域を小分けに処理する。形式ごとの保持能力を調べ、外観・色・編集性の損失をユーザーへ事前に示す。元の編集可能な作品は保護する。**

- **読み込み**：まず文書・レイヤーの構成や表示に必要なデータを取得する。大きな画像のすべてのレイヤー/画素を無条件に同時展開しない。編集対象の読み込みは操作待ちを最小にする。
- **書き出し**：版・出力条件を論理的に固定し、必要に応じて行/領域/タイル等の単位で描画・色変換・符号化する。全体中間コピーを避けられる形式・処理では回避する。ただし形式や効果の依存性から全体参照が必要な場合は、正確性を犠牲にしない。
- **形式互換の説明**：PSD/PSBやその他形式で、画素の外観、色空間/精度、レイヤー/マスク/効果/ベクター等の編集性を別々に評価してから変換する。拡張子を読み込めるだけで完全互換とは言わない。
- **データの安全性**：ネイティブ原本を保持し、変換失敗・権限拒否・容量不足・一括出力の部分失敗で元作品を壊さない。切り取りは内部コピーの成功を確認してから元を変更する。
- **共通基盤との整合**：R05の入力依存領域、R07の版固定/差分保存、R08の不変共有・履歴、R10のICC・精度、R11の非破壊編集データを保持し、不要な再計算/コピーを避ける。
- **性能は未保証**：実際の形式/プラットフォームごとに、初回プレビュー、全読込、メモリ頂点、出力時間、互換正確性を後工程で比較する。段階化だけで必ず速くなるとはしない。

## この段階では決めないこと

実際の画像codec、段階的復号の可能範囲、PSD/PSB等の対応深度、ストリーミング単位、UIでの互換差分表示、出力失敗時の後片付け、速度目標。PR #1で承認済の形式対応範囲を今回の方向記録だけで変更しない。
