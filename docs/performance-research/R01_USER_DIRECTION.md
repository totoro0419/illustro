# R01 — ユーザーが確定した研究・設計方針（2026-10-29 JST）

判断ID：**R01-U01**  
状態：**ユーザー承認済みの設計方向**（技術的成立・実装・性能の検証は未実施）  
対象：R01（入力・表示・座標）に加え、R02（操作順序）、R03（筆の意味・本線計算）、R06（資源予算）。

## 確定した方向

1. **仮線表示を採用する方向**：ペン操作に対して、正式な本線の計算完了前から線を視認できる表示を提供する。仮線は作品の完成結果と区別し、保存済み/確定済みと偽らない。
2. **本線を小さな実行単位へ分割する方向**：画素範囲・タイル等の単位で、正確な本線確定処理を長時間占有する単一仕事として扱わない。単位・粒度は固定しない。
3. **表示操作と本線確定をともに継続させる**：本線計算の進行中も指によるPan/Zoom/Rotateの受付・表示追従を維持し、仮線を含む作品が一体に動く。本線の確定も、指操作が継続していることだけを理由に停止・延期・極端に減速させない。
4. **両方を犠牲にしない**：キャンバス操作の快適性を実現するために本線を無期限に後回しにする方式、逆に本線を急がせるためにナビ入力を止める方式は採用しない。受理済み筆の取りこぼしや順序違いも認めない。
5. **正確性・一貫性を維持**：筆圧、入り抜き、色、重なり、タイル境界、Undo/Redo、保存時点、文書座標との一致を維持する。仮線から本線への置換で継ぎ目・二重表示・位置飛びを起こさないことを目標とする。

## 方針が意味しないこと

- GPUの実行順や割込みをアプリが自由に制御できる、という前提は置かない。GPU・CPU・メモリ帯域・OSからの入力配送が限界に達する場合、任意の負荷でゼロ遅延・本線確定時間の上限を保証することはできない。
- タイルサイズ、分割単位、投入間隔、優先度、表示と本線のメモリ構造、CPU/GPUの役割、仮線生成アルゴリズム、仮線→本線置換方式は**未確定**。旧Illustroの128/256pxなどを自動採用しない。
- 本判断は**仮線＋小分け確定を研究・設計の基本方針とするユーザーの承認**であり、PR #2のAI候補42案を一括正式採用したものでも、実機性能達成を確認したものでもない。
- 接地中の指ナビ時にペンを継続/一時休止するかという別の意味判断（既存DEC-02）は、この承認だけでは閉じない。

## 今後の検証条件

1. 太線・長線・短線・強制入り抜き・複雑筆の仮線表示と確定を、正解参照と比較する。
2. 本線処理中に長時間Pan/Zoom/Rotateを続けても、**入力受付/追従**と**本線の前進/完了**がともに成立するか測定する（継続操作中の進捗・最古待ち・完了時間を追う）。
3. 単独ナビと同時ナビ、単独本線と同時本線の両方を比較し、p50/p95/p99・停止・GPU/CPU時間・RAM・温度・電力を記録する。性能合格値は実測を経て定める。
4. GPUへの大仕事の一括投入、小仕事投入、その他の方式について、実際の画面反応と確定速度を同品質で比較する。GPUの占有状況を原因と推定だけで断定しない。
5. 途中の画面移動、連続した次筆、Undo、保存、文書切替の交錯を検査し、受理済編集の欠落・誤対象・データ破損を許さない。
6. 実機でOSからの入力配送と、アプリ受付後の画面反映を分離して測定する。
