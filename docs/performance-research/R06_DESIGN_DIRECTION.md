# R06 — 直近レイヤーの作業キャッシュ＋選択レイヤーを挟む上下二枚の表示合成

日付：2026-10-29 JST
状態：**ユーザーとの対話で基本設計方針を確定**。詳細仕様・実測・アルゴリズム採否は後工程。

## ユーザー発案

- 「直前五枚分とかをキャッシュに入れて、その他のレイヤーは押されたらさっと読み込む感じで良いんじゃない？」
- 「もしかるくなるなら、残りのレイヤーを選択されてるレイヤーを基準に画像として固定しちゃってもいいし」
- 「上下で挟む二枚とかでね」

## 確定する基本方針

**選択中の編集レイヤーを中央に置き、上側・下側の非編集中レイヤー群をそれぞれ表示用の合成キャッシュとして持つ。** 直近操作のレイヤー約5枚を編集用の再利用キャッシュに優先保持し、その他は選択・操作されたとき必要なデータを速やかに読み込む。数値「5」はユーザーの例示で、固定枠・容量保証とはせず、端末予算と実測に応じて調整する。

- **下側表示キャッシュ**：選択レイヤーより下の層をレンダリング結果としてまとめて再利用できる部分は再利用する。
- **選択中のレイヤー**：作業可能な正確なデータと描画対象を保持し、即時反応する。
- **上側表示キャッシュ**：選択レイヤーより上の層を表示用にまとめて再利用できる部分は再利用する。
- **重要な区別**：上/下の「二枚」は**表示結果としての論理的な合成キャッシュ**を指し、常時キャンバス全域のフル解像度画像2枚を確保することを要求しない。表示に必要なタイル・解像度で管理し、空白領域は確保しない。
- **非破壊**：非編集中レイヤーの原本・編集可能性・レイヤー順序・履歴・保存内容を保持する。表示用合成画像への置換によって元レイヤーを削除・不可逆にフラット化しない。
- **複雑な合成**：blend mode、クリッピング、グループ、調整レイヤー等は上下をRGBA2枚に単純平坦化して選択層と再合成すると元の見た目が維持できない可能性がある。正しさを保証できる部分だけ合成キャッシュとして切り出し、順序・依存性が残る箇所は独立評価または追加の中間表現を使う。
- **再利用と失効**：選択変更・レイヤー更新・表示/透明度変更・効果変更で、影響のある表示キャッシュだけ再計算する候補。選択だけで全画面の高価な再構成が発生しないよう既存キャッシュ再利用・先行読み込みを検討する。
- **予算**：ブラシの仮線・本線、Undo、効果、合成、保存、GPU転送を含めた全体メモリ予算を共有する。正本や未保存編集/Undo等を破棄可能キャッシュと混同しない。
