# R03 — ユーザー発案：輪郭・領域に基づく本線生成（2026-10-29 JST）

ID：**R03-U01**
状態：**全ブラシへ適用可否を研究するユーザー案。成立する範囲で従来方式より軽く、品質・意味が維持されるなら採用したいという条件付き方針**。現時点で特定ブラシへの正式技術採用、性能優越、実装完了を意味しない。

## ユーザー原案と範囲

- 「領域判定は？ 輪郭だけ計算して後は塗りつぶすみたいな」
- 「不透明に限らずです。この処理がより軽いのならば採用したい」

**不透明Gペンだけに限定しない。** 筆跡が作用する領域・輪郭と、その領域内での色・α・重ね塗り・粒・混色の評価を分け、従来のdab重ね描きより仕事を減らせるか、すべてのブラシ種別を対象に比較する。R01/R02で合意した仮線独立表示、筆FIFO保持、タイル単位での本線計算と両立させる。

## 技術仮説（未検証）

1. **領域/輪郭の集約**：筆圧・入り抜き・先端変形・軌跡から筆跡の被覆領域/境界を表現し、タイルごとに塗りの対象を絞る。各画素で何度も先端を合成する仕事を減らす可能性がある。
2. **内部作用の評価**：均一色・不透明なら領域内を一括塗りする候補。非蓄積半透明なら被覆率とαを計算して一回合成する候補。蓄積半透明、圧力変化、色変調、テクスチャ、Smudge/湿式は、最終被覆だけでは正しく再現できない場合があるので、必要な作用履歴・重複回数・色/下地の参照を別途保持・評価する候補。
3. **各筆に適した経路選択**：同値なブラシだけ集約を採用し、違いが出る場合は部分的な集約や従来厳密方式を使う。描画の見た目を変えることを高速化の成功とは呼ばない。
4. **計算と正式反映の分離**：タイルの計算/塗り評価は小分けにできるが、一筆の正式公開/仮線の削除/Undoの境界はR02で別途決める。

## 具体的な反証条件と比較

- 複雑曲線・自己交差・急な幅変化・短筆・穴・鋭角・タイル境界・アンチエイリアシングで、外周/被覆が従来結果と一致するか。
- 不透明・半透明・flow重ね塗り・色変調・テクスチャ/散布・消しゴム・湿式の結果を、筆/端末/画質別の独立な逐次描画oracleと比較する。α・筆圧・入り抜き・色空間の意味を保持。
- 実際のCPU/GPU時間、投入待ち、メモリ、一時データ、最初の表示応答、確定完了時間、同時ナビ追従を測る。輪郭構築/Boolean和集合/三角形化/走査線塗り/距離場生成が高コストなら不採用。
- 短い細筆から長い太筆まで比較して、採用の成立条件を客観的に決める。**すべてのブラシへ必ず同じ方式を強制するのではなく、すべてを研究対象とする**。

## 確認できる既存技術との関係

- Skia の `SkPaint::getFillPath` は一定のstroke設定から塗り領域パスを生成する例。筆圧変調/高度な筆/全条件の高速化を保証するものではない。一次資料：https://chromium.googlesource.com/skia/+/ab2621d3e2d2055096b9fbebf16ee443e4ea90fb/site/user/api/SkPaint_Reference.md
- MyPaint/Kritaの筆エンジン資料では、複数dabの合成による不透明度の非線形性、Smudgeの下地参照が明示される。単純な輪郭+一回合成だけでは全筆を同値にできない可能性。一次資料：https://github.com/mypaint/libmypaint/blob/master/brushsettings.json ／ https://docs.krita.org/en/reference_manual/brushes/brush_engines/mypaint_engine.html
