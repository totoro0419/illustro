## 1. D-022｜AST-001：素材を登録しても一覧で見つからない

**観察：** 参考画像を取り込んだ後、以前の「素材の種類」等の絞り込みが残り、新素材が画面に現れない。

**コード：** `apps/editor/src/assets/assetPanel.ts`。現在`kind`/ `filter`/`query`で素材を絞り、`importFile.onchange`は`addAsset`→`refresh()`のみ。絞り込みを解除したり、新規IDの行を表示する処理がない。素材セット取り込み`resumePendingImport()`も同様。

**実装確定：**
1. 取り込み結果の`id`を保持し、新素材が現在の絞り込みに隠れるとき、完了表示に「追加した素材を見る」アクションを出す。アクションは対象種別・表示状態・検索を適切に切り替え、必要なら一覧の表示上限を増やし、対象のカードへ移動して目立たせる。ユーザーが意図した絞り込みを勝手に恒久変更しない。任意で元の絞り込みを復帰できる。
2. 単体・複数ファイル・素材セット取り込み・途中再開・重複IDの解決後の実IDを考慮。失敗した素材について存在しないカードへ移動しない。
3. 素材の登録内容・既存タグ・フォルダーを変更しない。

**合格：** ほかの種類だけ表示・検索語も残った状態で参考画像を追加→成功通知から対象素材のカードが表示され、直後に「参考資料として開く」「整理」が使える。複数取り込みでも取り込んだ件数が一致。元の絞り込みも復帰可能。

## 2. D-023｜AST-002：タグ追加で6回も入力が必要

**観察：** タグを1つ足す操作でも、素材名・フォルダー・タグ・利用条件・作成元・メモの順に個別入力ダイアログが開く。

**コード：** `apps/editor/src/assets/assetPanel.ts` の `editMetadata` が6回連続で `appPrompt`。保存API `assets/library.ts:updateAsset(id,{name,folder,tags,license,origin,notes})` は1回の更新に対応済み。

**実装確定：**
1. `整理`を押すと**1つの編集画面**を出す。名前・フォルダー・タグ（カンマ区切りまたはチップ）・利用条件・出典/作成元・メモをラベル付きで配置し、画面が狭いときは縦にスクロールできる。
2. 必要な欄だけ変更して最後に`保存`を1回で実行。`キャンセル`では既存情報に一切変更なし。空の名前不可、既存の長さ/タグ数制限を維持。
3. 編集前の素材ID・内容の版・履歴・使用元の参照を維持。連打による二重保存を防ぎ、エラー時は入力値を保持。
4. UIは独自の安全なダイアログを使い、6つの個別プロンプトは撤去。キーボード、タッチ、文字拡大で全項目を操作できる。

**合格：** 「整理」1回→タグ1件を追記→「保存」1回→タグ反映。名前・元画像・既存素材IDは不変。キャンセルで無変更。ほかの項目も同画面で編集できる。

**合格：** PC/タブレット、通常・左利きで新しい参考画像が固定ツール列を覆わず「その他」がクリック可能。利用者が移動して保存した座標は再開後に保持。

## 4. D-025｜IO-005：SVGを書き出せてもIllustroへ読み戻せない

**観察：** Illustroで作成したSVGを同じIllustroで開くと「SVGはこの画面では出力専用です」となり、PNG変換が必要。

**コード：** `export/exchange.ts` の `exchangeFormat` は`svg`を認識するが`importExchange`は明示的に拒否する。書き出しは同ファイルの`svgGeometry`/`svgTextGeometry`で`<rect>`/`<ellipse>`/`<path>`/`<text>`、未対応レイヤーには埋込PNG `<image>`を出力し、<g>でレイヤー不透明度・可視状態を表現する。生成時にviewBox・幅・高さ・DPI由来の寸法を付ける。

**実装確定：**
1. **Illustro自身が書き出すSVG**の読み戻しを先に完成する。安全なSVGパーサを追加し、SVG寸法・viewBox・グループ・透明度・表示状態・座標と変形を正しく読み取る。
2. 対応する矩形・楕円・通常のパス・横書き文字は可能な範囲で編集できる図形や文字として復元する。旧書き出しのPNG内包`<image>`は元の表示に一致する画像レイヤーとして復元する。**編集できるかと見た目が保たれるかは別々に評価**する。
3. 未対応SVG機能は、許可された画像描画で外観を保てるなら明示した上で画像レイヤーへ変換する。正確に保てない場合は警告して拒否する。すべてのSVGで編集可能なベクター復元が可能だとは主張しない。
4. **安全性必須：** XML/SVGのサイズ・構文・画像数・寸法・参照先を制限し、script、event属性、外部画像/フォント/通信、foreignObject、危険なURL、無制限の再帰や巨大なdata URLを読み込ませない。外部取得なし。表示前に解析・検証する。元ファイルは変更しない。
5. メタデータ・レイヤー名・透明度・図形の寸法・色・表示と読み込み→再書き出しの差をテスト。座標の変換を二重適用しない。未対応の効果を無言で欠落させない。
6. SVG書き出し画面も「同形式で読み戻せる範囲」「一部は画像として復元」等を正確に説明する。

**合格：** 透過背景、色付き矩形、楕円、ベジェパス、対応する横書き文字、ラスターブラシを含むテスト作品→SVG書き出し→Illustroへ再読込→見た目/位置/サイズ/透過度が保存される。対応図形は編集でき、非対応部分は画像へ安全に変換される。悪意あるSVGや外部参照は禁止される。SVG以外のPSD/ORA/PNG等の読み込みは退行しない。

## 5. D-026｜CLP-003：作品切替後の貼り付けが無効

**観察：** 作品Aからコピー→作品Bへ切り替えると、貼り付けボタンが無効。ブラシを選び直すと貼り付け可能になる。

**コード：** `selection/clipboard.ts:ArtworkClipboard` は単一インスタンスにコピー記録を保持。`selection/clipboardPanel.ts:refresh` は `actions.canEdit()` と`clipboard.hasContent`でボタンを無効化する。`main.ts:activateOpened`では`documentActivationPending`・`documentReady`を切替えて新キャンバスを初期化。クリップボード表示更新は`withClipboardAccess`の最後等で行われるが、作品切替直後の再有効化には抜けがある可能性。

**実装確定：**
1. 作品の切替が完全に終わり編集可能になった直後に、既存のクリップボードパネル/ショートカットの有効状態を更新する。読み込み中だけ無効、完了すれば自動で有効にする。ブラシの再選択を要しない。
2. 作品Aからのコピーは保持し、作品Bの書き込み可能状態とサイズの制約を貼り付け前に分かりやすく表示。異なる作品寸法でも可能な合法操作は維持。
3. 未完了描線や復元中に先行して貼り付けない。作品切替が失敗した場合は整合性を維持する。OSクリップボード経路にも退行なし。
4. 元のD-012「位置を見ながら貼り付け」を維持し、貼り付けは1回のUndoで元に戻す。

**合格：** Aでコピー→Bへ即切替→ブラシ選択など不要で貼り付けボタンが有効→クリック/ショートカットで貼り付け→Undo/Redo。大小の異なる作品、選択範囲、画像/グループも関連範囲で確認。

## 6. D-027｜REF-004：資料から採った色の出典が履歴で分からない

**観察：** 参考画像から採色しても「カラー履歴」には色だけ残り、採色元の資料名や出典がない。

**コード：** `assets/referenceBoard.ts:sampleReferenceAt` は`options.color.choose(sampled)`を呼ぶ。`color/model.ts:ForegroundColor` の`history:RGB[]`は色だけを最大24件保存し、色重複も色だけで判断。`color/panel.ts:renderCollections` はRGBを色チップに変換。参考画像の`AssetEntry`には`name`/`origin`/`license`/`notes`があり、`BoardItem`にも`notes`がある。

**実装確定：**
1. **採色元メタデータ**（資料のassetId・boardItemId・documentId・資料名・出典表示等）を、資料採色時に色の履歴へ一緒に渡す。色全体の設定は従来どおりRGBを使い、描画色への悪影響を防ぐ。
2. 履歴の色チップで出典有無が分かり、タップ/キーボードから「採色元を確認」で資料名・出典メモを確認できるようにする。資料が現在の作品に存在するなら当該参考画像を開く・選ぶ入口も提供。
3. 保持形式は既存の`history:RGB[]`と安全に互換性を保ち、旧設定を読み込んだときは出典未設定として表示。色が同じでも最後に採った資料を正しく関連付け、色履歴の最大24件・クリア・保存・再起動を正しく扱う。
4. 資料を削除/別作品へ切替後でも色自体は使える。元画像がない場合は出典メモまたは「資料は現在利用できません」と表示し、無効な参照をたどらない。
5. 出典表示で画像や私的な資料を外部送信しない。ユーザー入力したファイル名・出典をHTMLとして解釈しない。

**合格：** 出典を記入した参考画像から採色→色履歴の色から資料名と出典を確認→必要なら資料を表示→画面を閉じて開いても保持。通常スポイト採色には架空の資料出典を付けず、履歴消去で出典も消去。

## 7. D-028｜SEL-005：長方形の内側ではなく全体が選択される

**観察：** ベクターの長方形の内側を選択しても全体が選択される。一方、塗りパネルの線画解析で領域を選び、選択範囲へ適用すると長方形内部だけが選択できた。

**コード：** `selection/panel.ts`には「線画で囲まれた部分を選ぶ」があるが、`pickAutomatic`で`action==='lineRegion'`のときは対象が強制的に`layer`。`selection/autoSelect.ts`の暗線・明暗しきい値による単純な連結探索は、`fill/pixels.ts:buildRegions`/外側判定/領域グラフとは異なる。ベクターの実描画結果をレイヤーから取得できているかも要検査。

**実装確定：**
1. 「線で囲まれた内側を選ぶ」では、**既存の塗り機能の領域認識**（`buildRegions`、領域ID、外側判定、必要な閉領域判定）を可能な限り共有。別の簡易推定アルゴリズムを追加して結果を食い違わせない。
2. ベクター長方形など、実際に見えている線を含む描画結果を参照できる。選択中のレイヤー/見える絵全体の参照元は明示する。対応しない場合は理由を表示。
3. クリックした領域だけを選択し、キャンバス端に連結する外側を誤選択しない。閉じていない線、白い線、透明背景、複数領域、描画倍率を検証。
4. 選択範囲の追加/削除/重なり、ぼかし・表示・履歴保存など既存操作を維持し、重い探索はWorker等で実行する。

**合格：** 塗りで正しく認識できるベクター長方形を、選択機能でも内側タップ1回で同じマスク（位置・画素）にできる。隣の長方形と背景は含まれず、選択解除・Undoも正常。線の隙間があるときは挙動を明示。

## 8. D-029｜COL-005：配色比較のボタンが下の操作バーに隠れる

**観察：** 色パネルの配色比較へマウスでアクセスできず、キーボード操作でのみ開けた。配色候補・明暗比・色覚比較自体は動作した。

**実装確定：**
1. 配色比較の入口を、色パネルのタブ/選色コントローラー近くなど**下部固定バーに隠されない、確実に押せる位置**へ配置。既存コントロールの邪魔をせず、表示順が理解しやすい位置を選ぶ。
2. タブレット・幅の狭い端末・右パネルのスクロール・文字とボタンの拡大・左利き表示で、開く/閉じると内部の操作ボタンを押せることを確認。

4. 可能なら「色」の機能検索/関連入口からも配色比較へ到達しやすくする。ただし本件の主目的は表示・クリック可能性。

**合格：** マウス・タッチの両方で見える入口から配色比較を開き、すべてのボタン/プルダウンを操作。操作バーが重ならず、キャンバス自体と既存の塗り・色選択の表示は退行しない。
