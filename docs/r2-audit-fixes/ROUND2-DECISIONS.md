## 2. 修正の決定事項とコード上の根拠

### 最優先｜D-021／SAV-003・SAV-008：書き出した作品を開けない

**実機観察：** 93 MB程度の作品を別名保存→「保存先の内容を確認済み」→同一ファイルを開くと「作品の区画保存情報を確認できません」。通常保存しても同様。バックアップ機能として重大。

**コードから確認できる不整合（有力原因）：**
- `apps/editor/src/persistence/persistence.worker.ts` の `encode-save` は `document`・`block:*`・`editor-state` 等を組み立てるが、部分レイヤー履歴を示す必須区画 `partial-raster-support`（`document.partial-raster.v1`）、変形情報の必須区画 `editable-affine-support`（`document.editable-affine.v1`）を追加する処理が欠落している。
- `apps/editor/src/persistence/portable.ts` の `createPortableDocument` は `hasPartialRasterSnapshots(snapshot)` と `hasEditableAffine(snapshot)` により必要区画を追加する。一方 `openDecodedPortableDocument` は必要区画欠落時に日本語のエラーを出す。
- worker内の書き出し時チェックはコンテナの `decodeIllustroFile` のみで、`openDecodedPortableDocument` による意味の検証は `legacyMigration` 時に限定される。
- `apps/editor/src/persistence/coordinator.ts` の `verifyExternalWrite` は読み戻したファイルのサイズ・ハッシュ照合までで、通常の作品復元処理は実行していない。

**実装決定：**
1. 必須区画の検出・挿入は `portable.ts` とworkerの共有可能な処理へ寄せ、構築経路の差をなくす。正確な区画IDと型は実装中に既存定数から取得し、推測した文字列を新設しない。
2. 出力ファイルをworker側で**通常の読み込みと同じ意味検証・復元処理**まで通し、失敗した場合は保存前に中止。ファイル書き込み／検証完了前に「保存成功」と表示しない。既存のディスク読み戻しハッシュ照合は維持。
3. 書き出し経路（新規保存・別名保存・既存ファイルへの上書き・ダウンロード）で同じ完全性条件を扱う。ダウンロードの場合はOSが保存した事実までは保証できないため、アプリが生成したデータの検証と区別する。
4. 旧版が作成した識別区画不足のファイルも、必要な全区画と編集履歴を安全に復元できることを個別に検査した場合だけ、**元のファイルを変更せず**救済コピーとして開く選択肢を検討する。完全性検査を無差別に無効化しない。安全に復旧できない場合は明示。
5. 巨大ファイルで余分な全量コピーを増やさない。約93 MB級でも時間・メモリを含めて検証。

**合格：** 部分レイヤー更新の履歴を含む作品と変形を含む作品を、別名保存→閉じる→同ファイル読込→作品・レイヤー構造・画素・履歴一致→もう一度保存→再読込まで成功。ファイル破損時は保存成功や無条件復元を出さない。旧形式も退行なし。先に小さな再現テストを作り、93 MB級をブラウザーで再現確認。

### 中優先｜D-017／AI-003：描画直後の解析で古い状態となる

**コード根拠：** `main.ts` の `installImageAssist` へ渡すcapture処理は `artwork.head` を取得してから `withClipboardAccess(...'read')` を待ち、`head` と現在の版が違うと拒否。`assist/panel.ts` はこの `valid` に依存し、エラーを出す。

### 中優先｜D-018／A11-001：アクセシビリティ拡大で2列UIが崩れる

**コード根拠：** `ui/accessibility.ts` は `data-illustro-text=large|extra` を付け、`ui/accessibility.css` は文字を16/19pxに拡大。`ui/c06.css` は `.c06-clipboard-grid` を常時2列、`ui/workspaceProfiles.css` の `.c04-workspace-actions` も常時2列。拡大時に空間が不足する構造。

**実装決定：**
1. 文字「大きい／さらに大きい」またはボタン拡大時、右パネルの使える幅に応じて2列グリッドを1列化する。右幅は少なくとも検査時344pxを再現、狭幅でも動作すること。コンテナ幅判定を使う場合は親の幅を正しく設定。
2. 項目名と操作部品を組で配置し、単語が1文字単位で切れない。必要な縦スクロールは許容、**横スクロール・重なり・ボタンの画面外消失は禁止**。
3. 標準サイズでは従来の2列構成を維持し、グローバルCSSの無差別変更で作画画面を壊さない。

**合格：** 右幅344pxで文字/ボタンを拡大し、ブラシ・塗り・設定などの2列の入力欄が読めて操作できる。幅288〜440px程度とタブレット画面でも確認。

### 中優先｜D-019／A11-006：英語の翻訳と読み上げ名が不一致

**コード根拠：** `ui/language.ts` は固定日本語文言を`english`辞書で変換し、変化したDOMを監視。`color/panel.ts` の「色相環の表示形式」「クラシック」「オービット」「色選択の表示モード」等に辞書未登録表記がある。言語選択UIやaria属性も翻訳範囲に含まれるが文字列が一致しないと日本語が残る。

**実装決定：**
1. 今回報告された色相環表示形式・オービット・クラシック・言語選択の読み上げ名を翻訳辞書に登録し、`aria-label`/`aria-description`/`title` も表示と整合させる。
2. 動的に更新されるaria値は言語変更イベントまたは既存の翻訳機構と整合させて即時更新し、日本語へ戻せば元に戻す。保存済みユーザー作品名・自由入力文言は自動翻訳しない。
3. 少なくとも問題発生画面の表示・選択肢・読み上げラベルをまとめて検査し、他画面の辞書全作り直しは行わない。

**合格：** 日本語→English→日本語を切替え、色相環・表示モード・選択肢・言語選択の読み上げ名が切り替わり、画面内の同一要素で言語混在がない。

### 低優先｜D-020／GST-004：ショートカット割当モードの説明が違う

**コード根拠：** `ui/shortcutSettings.ts` は登録を`mode:'press'|'toggle'|'hold'`で保存し、`startHold`とキーを離したときの`release`も実装済み。しかし割当一覧`render()`の表示文字列は「機能名＋キー」だけで、動作モードはツールチップ（title）に隠れている。実機で「単発」と誤解された点はここが有力。

**実装決定：**
1. 割当一覧の見えるテキストに `一度だけ／押すたび切替／押している間だけ` を明記する。選択・登録時にもモードが保存内容と一致するようにし、もし保持モードが非対応なら保存前に説明する。
2. 押している間だけの操作中は一時状態を表示し、キーを離すと元の道具・表示へ戻ったことが確認できるようにする。意図的にほかの道具へ切り替えた場合はその選択を尊重する。
3. キーの物理位置優先と文字キーの区別、登録済み割当の読み込み・再起動後の保持を維持する。

**合格：** 「表示移動」をholdとして登録→一覧に「押している間だけ」と表示→押下中のみ移動→離すと直前の道具へ復帰→表示にも反映。press/toggleとの違い、フォーカス喪失・キー繰返し・入力欄フォーカスも回帰確認。
