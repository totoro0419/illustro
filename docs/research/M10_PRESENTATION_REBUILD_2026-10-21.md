## Evidence and cause

1. **Original freeze dependency:** the start version creates formal GPU commands, CPU preview evaluation, GPU copy/readback and window view submission on the same window execution role. Its view fence/inflight and navigation suppression also delay fresh presentations. Main task duration and GPU queue completion are distinct; they are measured separately, not equated with hardware occupancy.
2. **Reproduced Worker reveal defect:** its `DrawingHost.setNavigationActive` suppresses `forwardView` throughout navigation. The window retains a viewport crop and affinely transforms it, so offscreen content is unavailable in the newly revealed region. In the native rapid-shrink fixture, the broken Worker's existing blue line has **0 of 1546 reference blue screen pixels** during the gesture, reappearing after release. The starting version and the first document-tile rebuild each retain all 1546 pixels under that same fixture. The final CI reruns all versions on both backends/routes. A viewport-only intermediate still exposed gaps when its GPU presentation was late; a retained document tile scene is required to remove that dependency.
3. **Destructive presentation lifetime:** `transferToImageBitmap` replaces the default canvas bitmap. A new picture must be completely populated independently of an old viewport cache's validity. The new atlas transport always initializes and writes every used slot; display snapshots always explicitly refresh the default framebuffer. For WebGPU, the display bitmap is transferred in the submitting task, BEFORE awaiting GPU acknowledgement; otherwise a current canvas texture may expire at the task boundary. Its immutable bitmap is sent only after that submitted work completes. This removes reliance on mutable/default buffer contents. This is a correctness requirement, **not a claim that every user's black frame was independently reproduced**.
4. **A rejected intermediate design:** tile transport with GPU upload/presentation still on window produced a 297ms main long task in a heavily concurrent software-GPU run. A twelve-stroke test also timed out. These are failures, not evidence of success. All display GPU API calls were moved out of window into a dedicated display role. A following native twelve-stroke case completed, including 1664 history versions spilled, with no observed main long task in that case. These exploratory observations are not the final isolated performance comparison.
5. **Save adapter omission found during regression:** the original Worker adapter exposes a remote `readTiles`, while the existing checkpoint reader expects local GPU resources. The new reader delegates its existing <=16 tile/1MiB batch through that port, validates the entire reply and its revision, and preserves local backend behavior. This is needed to retain PR38's finished-image cache, not merely its stroke replay fallback.

The cause of every physical phone incident cannot be inferred from a software GPU or source inspection. Direct hardware GPU duration, scanout, power/thermal behavior and complete device-loss recovery remain unmeasured.

## Final responsibilities

- **Window / BrushSurface / DrawingHost:** native input, receive-time document coordinates, Core transactions, semantic Undo admission, current view, bitmap ownership, atomic visible base/CPU-overlay retirement. It creates no GL/WebGPU context, raster commands or pixel readbacks. Changed document tiles also have a sparse compositor scene: one parent transform exposes their whole document extent while a fresh high-quality M08 viewport frame is still being computed. This is the retained display source, not a cropped transition screenshot. Preview bitmap layers share the latest view, and the fixed input viewport is retained.
- **Drawing worker:** the existing Session/Canonical worker, brush quality/forced taper/prediction, formal sparse 128px tiles, layer composition, TileHistory and bounded dirty tile export. At most one formal submission remains outstanding. It does not stop formal progress because a gesture is active.
- **Display worker:** a distinct retained document image using the accepted M08 presentation shader and pyramid. Only changed document tiles are uploaded. It continually accepts the latest view during navigation. Plain affine navigation uses the whole-document compositor scene without submitting another GPU viewport for every finger event; it refreshes the accepted M08 sampler when the interaction ends. Document tiles continue publishing throughout the gesture. Reference/seamless views retain the GPU sampler because they are not a single bounded document affine. It produces complete immutable display snapshots, and has no dependency on a canonical record, formal-stroke completion or history archive. It shares the physical GPU; no dedicated-hardware or hardware-preemption claim is made.
- **CPU preview:** existing coverage evaluator/slicing, with a stable sparse document grid for each stroke instead of a clipped screen crop. Navigation transforms existing images and cancels no pending samples/geometry. A newly started stroke may choose the current density; older grids are preserved.

Dirty document tile atlases are wholly initialized, transferred once, uploaded to the private display context, then closed. Base publication and its matching CPU-image retirement occur in the same window task. A visibility epoch rejects stale Undo images; rejected dirty keys are requeued, not lost. Reset also clears formerly occupied regions of the retained display document. A later composed-pixel probe exposed a 188ms first visible movement and ~370ms tail in an intermediate that refreshed a viewport on every finger event despite responsive rAF; it was rejected. Avoiding that redundant GPU image production while composing retained document pictures reduced the exploratory four-case first movement to 20–69ms, with no main long task. These are local software-GPU probes, not the final matched CI result or physical acceptance.

Display results carry content generation, visibility epoch and their actual source view; old asynchronous views cannot own the user's latest view.

## Removed from the new editor path

- window-side brush reconstruction, raster evaluation, GPU rendering and checkpoint readback;
- viewport-only base transport as the sole retained source;
- view forwarding suppression during a gesture;
- 120ms post-stroke and 80ms navigation quiet delays in the drawing role;
- CPU-to-formal guard snapshots and protection waits;
- one-tile-per-round-trip serialization used in the broken Worker;
- repeated DOM reordering and per-layer layout reads for every preview picture;
- synchronous exceptions escaping the worker protocol without replying to requests.

The directly embedded brush prototype keeps its accepted local display path. It does not require the editor's workers. No whole-canvas readback/copy per stroke, full-layer history bitmap, extra semantic authority or new save schema is introduced. The independent display role has one RGBA8 document texture (64MB at 4000px). The compositor scene adds only retained occupied 128px tiles, bounded by the document area (up to another 64MB at 4000px), not a new image for each stroke. Atlas and viewport resources are additional. These are estimated pixel-storage costs, not measured VRAM; actual phone memory and VRAM remain unverified.

## Platform references

- [HTML: transferToImageBitmap](https://html.spec.whatwg.org/multipage/canvas.html#dom-offscreencanvas-transfertoimagebitmap): transfer creates a new default bitmap, initialized black/transparent according to context alpha.
- [WebGPU: image copy and color encoding](https://www.w3.org/TR/webgpu/): external-image alpha/color encoding and device-owned GPU state. The transport checks premultiplied RGBA bytes on each backend rather than inferring correct color from API success.
- Existing major-app public behavior and adoption reasons remain in the canonical performance owner and M10 brush/preview research. This repair does not assert unpublished competitor internals.

Restore publication waits for the actual document-picture acknowledgement before reporting file/recovery completion. This fixes the independently observed M08 WebGPU seam-reload race where the semantic model was ready but the picture was still in transit. Stroke input and navigation retain their independent admission paths; no timeout delay is introduced.
