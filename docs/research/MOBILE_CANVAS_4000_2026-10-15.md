## Evidence and scope

The current sparse feedback path already preserves full-resolution artwork and updates changed tiles. It nevertheless composed each tile/layer to a 128px straight-alpha scratch image, then copied that image with premultiplication into the document-sized scene. The WebGPU path began and ended the large scene render pass for each tile/layer. The WebGL path repeatedly switched framebuffer targets. No assumption about a particular user's GPU is needed to count these calls.

A local 390×844 CSS / DPR3, memory-hint4, 4000² comparison used the same synthetic actual input: four curves of 61 samples at a requested8ms point interval,25ms between strokes,64px and256px G-pen, same code and rendering settings. Trusted touch is separately tested. Software Vulkan/SwiftShader is not an Android device. Cold shader compilation, frame batching and scheduling affect elapsed time; these local values are preliminary until same-run CI is available.

Initial256px total completion: WebGL2 7187.3→5297.6ms; WebGPU 10466.3→7397.9ms. Scene render passes on WebGPU 1195→17. Draw calls on WebGL2 7121→5469. ## Chosen change

For at most eight tile-local overlays, use the existing quantized straight-alpha composition equations and premultiply directly into the retained scene. `compose()` already rounds each stroke to RGBA8; the intermediate scratch texture does not add required precision. The direct vertex mapping keeps document-space positions, and the fragment preview reads use the same tile-local coordinates as the prior scratch path. Strict deposition, brush geometry, actual/predicted input, taper, revision ordering, history cache capacity, portable format and screen backing resolution are unchanged.

All changed scene regions are cleared first. WebGPU direct tile/layer draws then share a render pass until an oversized overlay group requires the exact scratch fallback. End the scene pass before writing shared scratch textures; resume it afterwards. WebGL keeps the scene framebuffer bound for contiguous direct draws. Layer and stroke order remain unchanged. More than eight overlays still use bounded chronological scratch groups. No persistent cache or extra artwork-sized texture is added.

## Public primary sources consulted

- Arm, Efficient render passes with OpenGL ES: https://support.arm.com/documentation/101897/0304/Fragment-shading/Efficient-render-passes-with-OpenGL-ES — advises avoiding returning repeatedly to render targets. This supports the design choice; it does not establish the user's GPU type or speedup.
- Krita, Instant Preview: https://docs.krita.org/en/reference_manual/instant_preview.html — separates quick feedback from full stroke calculation, with documented restrictions and possible popping. Illustro retains its existing full-precision sparse feedback; no reduced brush/image resolution is adopted here.
