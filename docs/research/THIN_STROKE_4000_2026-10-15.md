# Thin strokes on a 4000px canvas

Status: EXPERIMENTAL. Automated/browser results do not establish physical Android performance or user acceptance.

Base: PR28 `efaf43766aa96befa18984f34d8853543c7d7eed`, tree `ce4808ca868938068e9de942d123c592120c8219`. This preserves the additional color-wheel fixes, ordered stroke handoff, continuous Undo and wide-brush work reduction. No prior PR or production branch is merged or overwritten.

## Measurement and feasibility

The first mobile-width comparison covered actual 8/16/32/64px G-pen input at4000². Previous submissions were dominated by repeatedly shading the whole backing image, including unchanged pixels and frames with no changed tile. WebGPU repeated unchanged presentation took about75ms in the local SwiftShader environment. This includes browser/queue completion and is not isolated GPU execution time. Tile-local scene work and mip draw counts also increase with document-space path length.

Adjacent mip rectangles alone reduced command counts but had a small/noisy effect on elapsed time. Merely reducing formal batches to16 made the queue settle more slowly and was rejected. The chosen design combines reuse of final screen pixels, exact rectangle unions, omission of redundant intermediate feedback, and a maximum32 normal formal batches per submission. Atomic history reconstruction can still use128 while presentation is held. The existing pixel-work budget, ordered canonical jobs and admission/memory bounds remain in force.

A local matched, alternating, three-trial comparison of16px strokes gave active-input submission-completion medians101.4→27.85ms on WebGL2 and202.9→115.7ms on WebGPU. Four-stroke total medians2813.8→2658.7ms and2972.0→2674.7ms include the same paced input. First-stroke input latency did not improve uniformly in every trial. These are preliminary software-GPU measurements; the exact-source CI evidence supersedes them. No all-device one-frame/4000px smoothness claim is made.

## Implemented plan

1. Keep one RGBA8 image at the actual screen backing dimensions, capped at32MiB. It is derived display state, never artwork, history, save data or the only representation of a stroke. There is no additional4000² history/preview copy. Old viewport images are released on resize and destruction.
2. Reuse the unchanged presentation shader, image sampling, rotation, paper and shadow. Project changed document tiles conservatively to screen rectangles, including mip/area/bilinear sampling support and a rounding guard. Recompute only their exact union. WebGL2 blits the completed screen image; WebGPU copies it with a one-texel-load render pass. RGBA8-to-RGBA8 preservation is independently checked against direct rendering.
3. Track screen invalidation independently of mip invalidation, including100% views where no mip is used. Initial render, changed view/backing, clearing and missed generations invalidate the screen image. Seamless/reference views, view-only motion, disabled cache and over-budget dimensions use the existing direct presentation path. Unchanged WebGL2 content can retain its preserved drawing buffer. WebGPU canvas textures expire, so each requested presentation still copies the retained viewport image into the current texture, including when no viewport pixels need reshading. The pixel harness captures submitted canvas writes in the same task, before automatic expiry: waiting for the completion callback first intermittently read an empty canvas even with the original direct renderer. Extra checks request unchanged cached frames after a task boundary.
4. Final ended feedback stays visible while its private canonical coverage is computed. Do not recompose the same tile just because intermediate private coverage advances. Every strict tile commit, missing/unfinished feedback, surface mismatch and affected history/cancel operation still invalidates the picture. No formal command or accepted input is omitted; completion waiters still require formal work and presentation.
5. Merge adjacent/overlapping mip/scissor rectangles without changing their pixel union. This removes redundant draws and repeated rounded-edge work. Canonical geometry, brush reconstruction, deposition equations and forced taper are unchanged.

## Public primary sources

- Adobe Photoshop performance preferences: https://helpx.adobe.com/photoshop/using/performance-preferences.html — documents caching high-resolution redraw and smaller evaluation tiles for brush/fine edits. This supports choosing local updates; it does not describe Illustro or prove a particular implementation inside Photoshop.
- Arm render-graph guidance: https://learn.arm.com/learning-paths/mobile-graphics-and-gaming/render-graph-optimization/understanding-your-render-graph/ — inspect work and data movement contributing to the final displayed image.
- OpenGL ES scissor: https://registry.khronos.org/OpenGL-Refpages/es3/html/glScissor.xhtml ; blit: https://registry.khronos.org/OpenGL-Refpages/es3.0/html/glBlitFramebuffer.xhtml .
- WebGPU specification: https://www.w3.org/TR/webgpu/ ; queue API: https://gpuweb.github.io/types/interfaces/GPUQueue.html . Completion callbacks are distinguished from physical display timing.
- Krita Instant Preview: https://docs.krita.org/en/reference_manual/instant_preview.html — documents separate feedback and final computation, restrictions and a default threshold for larger brushes. No reduced artwork or preview resolution is introduced here.

Physical Android/pen, thermal throttling/power, isolated GPU time, actual VRAM/RSS and input-to-photon remain unverified. Narrow-stroke cold/first-input outliers must remain visible in the report. A faster median is not a promise of sustained60Hz on the user's hardware.
