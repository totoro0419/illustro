# 第③段階 UI/UX設計・試作操作と確認台帳

**正式UI承認ではない。** 従来のAurora明色、黄橙アクセント、左Rail、右可変Workspace、中央Canvas、Quick、固定Layers/Undo/Redo/反転は継承。スマホ/タブレット/PCの試作配置はブラウザー上のレビュー用で、実機とは区別する。

## 変更箇所とその狙い

- 通常Undoと候補Session内Undoを分離。候補中も「作品Undo/Redo」ボタンで独立編集を扱える。通常操作の副作用はaction別に区別し、Undo検索で偽の作品編集を作らない。
- レイヤーの追加、表示、合成モードはモデル正本に入りUndo/Redo対象。選択中レイヤーは画面コンテキスト。
- Focus中の色・レイヤー要求は一時Workspaceとして表示。Focus状態自体は維持し、閉じればキャンバスへ戻す。
- 760px以下は下部シート、Session操作帯の高さを別予約するCSSに変更。761〜1000pxの中間幅はCanvas残余幅を考慮しWorkspaceを制限。
- 色選択のSV面をpointer/arrow key操作可能な**簡易UI試作**に変更。現行のICC/色環実装ではない。
- 二指操作の重心アンカー補償計算を変更。ペン＋指の実物試験は未実施。
- ストローク表示は変更がないSyncでDOM再構築しない。正式レンダラーの性能とは無関係。

## 8つの制作シナリオ

| 作業 | プロトタイプで扱えること | プロトタイプにないもの |
|---|---|---|
| 1 新規キャンバス→筆 | Home→New→Brushの入口・模擬線 | 実際のキャンバス新規作成、筆正式処理 |
| 2 ラフ/線画/色の層 | Layer Page、層の追加/選択/目/合成とUndo | レイヤー画素と合成GPU |
| 3 筆/色/太さを連続変更 | Rail・サイズ・Color SV・Quick | 高品質Stroke/16F/筆カスタム |
| 4 線画を参照したFill | Fillの機能詳細と候補UI | 線の正確な閉領域と全層参照Fill |
| 5 Selection/Transform/Cancel | 対象候補Sessionと適用/取消/作品Undo | Warp本体/正式選択マスク |
| 6 非破壊FX調整 | 機能を探索しSessionの状態を確認 | FXの実画素評価とcache |
| 7 Save/中断/再開 | SaveFence風の要求時点固定を模擬 | Native保存、OPFS、アプリ再起動耐久 |
| 8 完成作品Export | 出力機能の導線を確認 | PNG/JPEG/WebP/ICCの実書出 |

## 対象機器の検証方法

PC: 1440x900/1180x820を含めて左Rail＋Workspaceを検査。Tablet: 1180x820や800x600、ペンと二指同時入力、縦/横、OSジェスチャー、分割画面。Phone: 390x844/320x568/740x360でシート/適用/取消/拡大文字/キーボード/安全領域を検査。

Chromiumのviewport変更や合成PointerEventは**実機検査ではない**。DOM hit-test、focus、隠れたパネル、遷移の一部を先行検査し、実ペン・筆圧・多指・モバイルOSイベント・パフォーマンスは別途実機で検証する。

## ユーザーによる判断待ち

1. Focus中の色/層パネルは一時表示でよいか、よりCanvasを確保するFloating形が自然か（スクリーン比較と実操作で決める）。
2. Sessionがあるときの「候補Undo／作品Undo／作品Redo」のラベルと優先順位。明示切替が理解され、通常描画を邪魔しないか。
3. 横持ちスマホでWorkspaceと固定操作帯のサイズ・閉じ方が適切か。
4. 変形後の消去/混色を従来のTransformから切り離した位置で固定することが直感と一致するか。

ユーザーによる正式UI承認を代行・記録しない。技術的に実証されていない箇所を「操作性合格」と呼ばない。
