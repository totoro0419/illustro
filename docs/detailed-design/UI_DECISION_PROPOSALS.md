**承認履歴**：旧Transformの再編集時、後段のPaint/Erase/固定SmudgeをDocument座標に固定する意味（AUD006）は既に本人承認済み。加えて本対話でFocusの**A案**に本人が明示的に「A」と回答したため、Focusは製品操作方針として正式採用する。さらにユーザーが本対話でUndo A案を「そうする」と承認したため、**FocusとUndoの操作方針は正式確定**。残るスマホ横画面についてユーザーから「**アイビスを強く参考にして**」との設計方向が明示された。参考方針は確定、具体的なC案レイアウトの本人承認と実機操作評価はまだない。UIの本人判断は実機・初見ユーザー試験のPASSを意味しない。

## 1. Focus中の色・レイヤーアクセス

**正式採用A（本人承認済み）：Focusを維持したまま必要な色/レイヤーの一時Panelだけを開き、閉じたら元のFocusへ復帰。**

- 対案B（不採用）：色/レイヤー操作を選んだら標準レイアウトへ戻り、Focusは再操作が必要。通常操作で勝手にこれへ切り替えない。
- 理由：Focusの目的は画面の雑音を減らすことだが、実際の描画では色・レイヤー操作が繰返し発生する。Aなら作業文脈を維持できる。Bは通常配置へ戻る経路が明快という利点がある。
- Aの制約：Panelを開く操作の可視性/閉じるボタン/Escape、Focus復帰、Panelが開いている間の入力許容範囲、キャンバスの適切なサイズ・Undo/Saveを失わないこと。操作方針Aは本人が正式承認済み。パネルが開いていてもFocus状態は維持し、閉じる・Escapeで元に戻す。
- 試作の通常動作もAに固定する。中間幅420px最低描画列などのDOM試験を維持・追加する。**実端末の使用感や所要時間は未測定**。

## 2. Undoの作用先と視覚表現

**正式採用A（本人承認済み）：一般操作のUndo/Redoは常に「作品Undo/Redo」、Transform等の未適用候補だけはSession帯に「候補Undo/Redo」を表示。参考資料・試筆・作品管理は各対象名を添えた専用Undo/Redoとする。**

- 対案B（不採用）：操作中の焦点に応じて固定Undoの意味を暗黙に切り替える。Bはボタン数を減らせるが、作用先の予測が難しく、AUD001/003/016で問題となった誤操作を再導入するため不採用を推奨。
- Aの制約：Undo前に対象を識別でき、対象の変更に伴い作用先が黙って変わらない。作品の独立した操作をUndoしてもSessionは保持。候補Undoは作品の過去履歴を動かさず、CancelはSessionだけを破棄。
- 比較課題：変形候補を編集→別レイヤーに描画→固定「作品Undo」→候補「候補Undo」→取消→参考資料移動→資料の専用Undo。どの履歴が変化したか利用者が説明できるか。
- **本人による設計方針の承認は取得済み。** ただし、実画面を操作させた作用先理解・初見利用者の成功率は未実施。試作に候補Undo/Redo双方を明示表示し、モデル/DOMで作品Undoとの非干渉を回帰する。

## 3. スマホ横画面でのSessionとWorkspace — ibisPaint参考C案

**正式指示：ibisPaintを強く参考に再設計する。具体的なC案は提案・試作段階で未承認。** [一次資料・参考範囲・実装差分](IBISPAINT_PHONE_LANDSCAPE_REFERENCE.md) を参照。

- ibisPaintの公式「ツールバーとツール選択」では、ブラシ/消しゴム切替、ツール選択、設定、カラー、Undo/Redo、レイヤーなどの高頻度操作が主ツールバーに集まる。選択ツールはポップアップで一覧化できる。
- **C案：スマホ横画面の下部をコンパクトな主要操作バー**にし、左Railは横持ち時だけ隠す。色・レイヤーは必要時の右側コンパクトPanel、ツール一覧はポップアップ、太さ設定も一時表示。未適用Sessionの候補Undo/Redoは作品Undo/Redoから独立して画面内へ表示する。
- 従来Aの「描画領域優先」を継承するが、横画面で大きな全面下部Sheetを常用しない。従来Bの「大きい常時Dock」は採用候補から外す。ただしこれは**設計案の変更**であって、本人がCの具体寸法を承認した意味ではない。
- ibisPaint公式のレイヤー常時フローティングウィンドウはタブレット/PC限定。Illustroのスマホ一時Panelは**独自適応**として設計し、元アプリのスマホ既定動作だと記載しない。
- 740×360でCanvas幅・タッチ標的・ツール選択・レイヤー開閉・候補帯を実DOM検査、390×844で縦画面を回帰。実OS・実指/ペン・長時間作画・定量初見評価は未実施。

## 4. 承認と実測を分けた判定規則

- 本人がA/Bの**操作意味とレイアウト方針**に同意 → Stage③の意思決定の「承認」。
- 実際のプロトタイプ・実画像・端末を触って測り、指定操作を迷わず行えた → その条件の「利用者検証」。本人の口頭承認だけを初見実測PASSと記載しない。
- 製品実装が必要なGPU/Native/物理保存/筆圧/動作速度 → Stage④で正式検査。Stage③のモデル検査でPASSにしない。
- FocusとUndoのAは正式決定済み。**スマホ横画面はibisPaintを強く参考にする方針を本人が明示**。C案の具体的UIはまだ本人の操作承認がなく、端末で比較して決定する。
