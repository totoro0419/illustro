# Stage③ — ユーザーによるUI最終判断（Focus承認済・残り2件未承認）

**承認履歴**：旧Transformの再編集時、後段のPaint/Erase/固定SmudgeをDocument座標に固定する意味（AUD006）は既に本人承認済み。加えて本対話でFocusの**A案**に本人が明示的に「A」と回答したため、Focusは製品操作方針として正式採用する。残り**Undoの提示／スマホ横画面**の2件は未承認。UIの本人判断は実機・初見ユーザー試験のPASSを意味しない。

## 1. Focus中の色・レイヤーアクセス

**正式採用A（本人承認済み）：Focusを維持したまま必要な色/レイヤーの一時Panelだけを開き、閉じたら元のFocusへ復帰。**

- 対案B（不採用）：色/レイヤー操作を選んだら標準レイアウトへ戻り、Focusは再操作が必要。通常操作で勝手にこれへ切り替えない。
- 理由：Focusの目的は画面の雑音を減らすことだが、実際の描画では色・レイヤー操作が繰返し発生する。Aなら作業文脈を維持できる。Bは通常配置へ戻る経路が明快という利点がある。
- Aの制約：Panelを開く操作の可視性/閉じるボタン/Escape、Focus復帰、Panelが開いている間の入力許容範囲、キャンバスの適切なサイズ・Undo/Saveを失わないこと。操作方針Aは本人が正式承認済み。パネルが開いていてもFocus状態は維持し、閉じる・Escapeで元に戻す。
- 試作の通常動作もAに固定する。中間幅420px最低描画列などのDOM試験を維持・追加する。**実端末の使用感や所要時間は未測定**。

## 2. Undoの作用先と視覚表現

**推奨A：一般操作のUndo/Redoは常に「作品Undo/Redo」、Transform等の未適用候補だけはSession帯に「候補Undo/Redo」を表示。参考資料・試筆・作品管理は各対象名を添えた専用Undo/Redoとする。**

- 対案B：操作中の焦点に応じて固定Undoの意味を暗黙に切り替える。Bはボタン数を減らせるが、作用先の予測が難しく、AUD001/003/016で問題となった誤操作を再導入するため不採用を推奨。
- Aの制約：Undo前に対象を識別でき、対象の変更に伴い作用先が黙って変わらない。作品の独立した操作をUndoしてもSessionは保持。候補Undoは作品の過去履歴を動かさず、CancelはSessionだけを破棄。
- 比較課題：変形候補を編集→別レイヤーに描画→固定「作品Undo」→候補「候補Undo」→取消→参考資料移動→資料の専用Undo。どの履歴が変化したか利用者が説明できるか。
- **本人によるUI理解・承認は未実施**。モデル/DOM上は独立履歴が動作する。

## 3. スマホ横画面でのSessionとWorkspace

**推奨A：縦方向の表示領域が少ないとき、作品Undo/Redoは画面下の小型固定操作、候補Undo/取消/適用はSession帯へ分離。Workspaceは通常非表示で要求時のみ開くシートとし、開いていない間はキャンバス領域を最大化。**

- 対案B：通常のDock/Toolbarを常時表示。AよりCanvasを遮りやすいが、設定は常時目に入る。
- Aの制約：候補操作/作品Undo/色/レイヤーへの入口を一意にする。誤って閉じてもSessionが消えない。Session帯とシートの高さは実測/ResizeObserverから衝突を避け、画面が狭い場合はスクロール可能にする。
- 参照Viewport：740×360。ブラウザーgeometryと中央hitは検証済み、**Androidの実OSキーボード、ペン・指、利き手、長時間描画の操作性は未検証**。

## 4. 承認と実測を分けた判定規則

- 本人がA/Bの**操作意味とレイアウト方針**に同意 → Stage③の意思決定の「承認」。
- 実際のプロトタイプ・実画像・端末を触って測り、指定操作を迷わず行えた → その条件の「利用者検証」。本人の口頭承認だけを初見実測PASSと記載しない。
- 製品実装が必要なGPU/Native/物理保存/筆圧/動作速度 → Stage④で正式検査。Stage③のモデル検査でPASSにしない。
- FocusのAは決定済み。未承認のUndo・横画面は推奨Aを設計案として提示しているだけであり、本人が判断するまで確定扱いにしない。
